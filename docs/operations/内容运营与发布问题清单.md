# 内容运营与发布问题清单

## 使用边界

本清单是候选采集、事实审核、单条发布和公网验收问题的唯一 tracked 入口；不展示给网站读者。task 不是问题数据库，跨 task 只传问题 ID、当前状态、证据路径、责任人和下一动作。

只有同时具备可验证证据和实际影响的问题才登记。想法、偏好、无证据猜测和已经由现有规则覆盖的正常状态不进入清单。发现者可以登记问题，但不得借登记自行修改产品、规则或工程实现。

本清单覆盖内容运营全链路：来源采集与覆盖、EvidenceCandidate、事实审核、Brief/Article/Practice 字段适配、slug 级命令、独立内容提交、push、EdgeOne、公网验收、失败重试和 workspace 清理。产品 DRAFT、视觉意见和新页面能力不在本清单另建条目；它们必须转入 `docs/iterations/candidates/` 或当前正式迭代，并保留本问题 ID 作为来源引用。

## 统一状态与字段

状态只使用：

`待评估 → 已确认 → 待实施 → 实施中 → 待验收 → 已关闭`

无法继续时使用 `等待上游输入`；它表示责任 task 已记录所缺输入、回传对象和恢复条件并结束当前回合，不表示持续调用等待或轮询工具。经评估不处理时使用 `不处理`，并记录理由。

每项至少包含：

- 唯一 ID、状态和发现日期；
- 事实证据、影响与风险；
- 当前临时控制；
- 责任域与责任 task；
- 是否需要产品版本；
- 已批准方案或下一动作；
- 完成后的 commit/tag（如适用）与验证结果。

## 处理规则

- 内容运营内部规则问题可以独立 tracked 文档提交修正，不改变产品版本或 tag，也不触发部署。
- 只有公开内容对象、信息架构、页面投影、视觉/响应式或发布能力合同需要改变时，才由产品与视觉 task 评估并转入 `docs/iterations/current.md`。
- Engineering 只实现已经批准并进入当前迭代的问题，不顺手修复清单中的其他项。
- 内容提交只能包含目标 Observation 与必要 approved media，不夹带问题清单或规则修正。
- 关闭问题时保留原问题、修复事实和验证结果；不删除记录，不把完整 task 历史复制进来。

## 转入规则

- 只影响采集、审核、内容结构或既有发布命令的，留在本清单独立关闭。
- 影响公开内容对象、页面结构、视觉/响应式或发布能力合同的，保留本清单 ID，并转入 `docs/iterations/candidates/`；确认后才进入 `current.md`。
- 影响 Robotaxi 上游事实、系统状态或媒体审批的，回传 Robotaxi 责任 task；xingbuild 只记录证据边界和引用路径。
- 一个问题只能有一个 owner；跨 task 消息只传 ID、事实源、当前状态、阻断和下一动作。

### OPS-CONTENT-005：共享 main 与部署门禁使内容发布依赖产品工程时序

- 状态：已确认
- 发现日期：2026-08-02
- 事实证据：`publish-content.command` 强制当前 checkout 为 clean `main`，并要求首次发布时 `origin/main == HEAD^`、同提交重试时 `origin/main == HEAD`；`scripts/content-scope-check.mjs` 复用同一门禁。内容提交 `6974b10` 后，远端被治理提交 `b02ee7a` 推进，原内容同 HEAD 重试按规则停止。
- 影响与风险：产品/Engineering 在共享 checkout 留下未提交文件时，内容不能发布；内容构建后主线前进时，内容必须临时换 clone 或重做基线。若放宽门禁，可能把旧构建或产品文件混入内容发布。
- 当前临时控制：内容 task 使用从最新 `origin/main` 刷新的干净隔离 clone，单 slug 检查、提交、push、部署和公网验收；不修改 `current.md`、产品版本/tag 或产品工程文件。
- 责任域 / 责任 task：xingbuild 内容发布能力；Engineering 负责命令与测试，内容 task 负责目标 slug；产品与视觉只确认公开发布能力是否变化。
- 是否需要产品版本：当前不进入 `v0.22.0`；若发布命令合同改变，单独形成后续内部发布能力版本。
- 根因与处理方案：不是内容判断或 v0.22.0 串行边界，而是共享 checkout 假设与缺少短时 release lease。候选方案为唯一干净内容 checkout、fetch→目标提交→push→build/deploy→verify 临界区租约，以及部署前再次确认远端仍为目标 HEAD。
- 下一动作 / 恢复条件：先保留独立运营，待产品责任方确认后形成最小 Engineering 合同；完成专项测试和同 HEAD 重试/主线前进反例后再关闭。
