# 经营观察信息源与覆盖合同

状态：生效。适用于定时与按需 Ops 采集；不授权写稿、审核、提交或发布。

## 采集目标

发现会改变 Robotaxi 准入、运营、安全、产品能力、合作扩张或经营资本判断的可核验事件，而不是追逐新闻数量。每次运行只形成候选（candidate）与内部覆盖记录。

## 固定来源优先级

| 级别 | 来源 | 使用方式 |
| --- | --- | --- |
| P0 | 监管/政府、法定公告、交易所与公司 IR/新闻室 | 关键监管、许可、安全、财务或正式运营事实的优先依据。 |
| P1 | X 原帖：可验证的监管者、公司官方账号、负责人、研究者、行业记者与一线专业人士 | 实时优先发现与追踪。保留原帖 URL、账号身份/角色、发布时间与访问时间；按账号主体标注 company statement、media report、opinion 或线索。 |
| P2 | 合作方、车队/城市/供应商的正式公告；可信专业媒体 | 补全多方事实或交叉核验。 |
| P3 | 行业研究机构、学术/安全组织的公开报告 | 用于方法、数据和趋势，不以二手转述替代原报告。 |

P1 的时效优先级不低于 P0；事实等级不由平台决定，而由发帖主体、原始证据和可复核性决定。关键经营事实除监管或公司正式披露外，必须获得独立原始来源或可信报道交叉验证。

## 内部来源注册表

Ops 在首次覆盖和每次发现稳定高价值来源后，维护被忽略的 `.content-workspace/ops/source-registry.md`。定时采集先检查该注册表，再按明确缺口补充来源；不得每次从无边界搜索开始。

每个注册表条目至少包含：来源名称、平台/原始 URL 或 X 账号、可验证身份和角色、P 级、覆盖主体/城市/维度、适用主张性质、最近核验时间，以及不宜独立采用的限制。新增来源必须先验证身份与历史信噪比；失效、改名、不可访问或持续低价值来源要记录原因后降级或停用。

## 两种执行模式

| 模式 | 触发 | 窗口 | 输出 |
| --- | --- | --- | --- |
| 定时采集 | 工作日固定运行 | 上次成功采集结束至当前时间 | 新候选、去重/no-change、覆盖记录。 |
| 按需采集 | 用户提出主体、城市、事件或回溯窗口 | 明确指定的事件或日期范围 | 同一候选包；不得改变发布门槛。 |

两种模式共享同一来源清单、证据模型、去重规则与写入边界；按需任务不得绕过定时任务的核验要求。

## 每次 Ops 的最低记录

- 采集窗口、运行模式、P0/P1/P2/P3 已查来源或账号；
- 命中事件、原始 URL、主体、事件日期、发布时间与访问时间；
- 维度、主张性质、支持事实、冲突/未知项和去重结论；
- 候选路径或明确的 `no-change`，以及未覆盖/不可访问来源。

候选只写入被忽略的 `.content-workspace/imports/`，来源注册表和覆盖台账只写入被忽略的 `.content-workspace/ops/`，均遵循 `ObservationPublication → EvidenceUnit → Source` 的事实边界。它们不得进入生产 bundle 或读者界面。

## 终端化边界

Ops 可以使用固定终端脚本做来源清单检查、日期窗口、URL/字段完整性、去重和 candidate 验证；不能由脚本自动决定新闻价值、事实等级、公开文案或发布。内容审核通过后才使用单 slug 的 `content:approve` 与 `publish-content.command`。
