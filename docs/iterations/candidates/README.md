# 产品优化候选入口

这里是所有尚未进入当前版本的产品、视觉、页面、内容对象或发布能力优化的唯一共享入口。

## 文件规则

- 一个候选一个 Markdown 文件；文件名包含稳定候选 ID。
- 候选至少写明：候选 ID、来源问题/事实、优化目标、影响范围、`executionAuthorization: pending | confirmed`、责任 task 和下一动作。
- `pending` 表示等待产品判断或用户确认；`confirmed` 表示允许产品 task 在当前版本完成后自动纳入下一次版本规划。
- 候选不修改 `current.md`、VERSION、代码、依赖或线上状态。
- 当前版本验收发现的问题不进入这里，直接形成当前版本的修复版本。

## 启动规则

产品/视觉 task 每次准备启动版本时只检查本目录：

1. 没有 `confirmed`：保持最近发布版本基线，不创建新版本；
2. 有一个或多个 `confirmed`：综合评估后形成一个正式版本方案，并写入 `current.md`；
3. 尚未纳入的候选保留原文件，等待后续版本；不需要 roadmap。

运营问题若影响产品能力，在运营问题清单中保留原问题，并创建一个候选文件指向该问题 ID；运营问题本身不复制产品方案正文。
