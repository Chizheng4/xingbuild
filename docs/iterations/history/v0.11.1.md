# v0.11.1 内容入口结构收口

## 问题

`v0.11.0` 已建立总体页面与空态母版，但 Robotaxi 实践模块仍以内联 JavaScript 作为内容入口，观察简讯尚未从 `ObservationPublication` 的明确投影读取。后续填充真实媒体和经核验简讯时，容易再次触及页面组件或复制内容事实。

## 实现

- 将 Robotaxi Practice 与模块配置迁入受控内容目录；以当前有效媒体 manifest 解析模块媒体，并校验文件、16:10 比例、来源版本/地址、可用性和真实模块级链接。当前没有已批准媒体或模块，因此配置诚实为空。
- 将可选 `brief` 投影纳入 `ObservationPublication` schema；日期和维度只从父对象继承，避免重复事实。既有两篇公开观察未补写 brief，继续不进入信息流。
- 建立统一的 brief 投影与查询层。Practice 只读取 Robotaxi 范围的最新公开简讯；企业经营体系读取全站最新公开简讯。无公开 brief 时两个页面均不渲染空 rail。
- 将 rail 由固定条数改为基于完整条目测量的高度预算；生产读取层只消费 `content/observations/`，草稿和导入文件继续隔离在 ignored workspace。
- 删除旧 `src/content/observationBriefs.js` 作为内容源，并补充 Practice、Brief、Rail、空态和范围选择合同测试。

## 验证

- `npm run release:check` 通过，50 项自动测试全部成功；
- `git diff --check` 通过；
- 真实浏览器最小回归确认当前零公开 Brief 时企业经营体系不渲染空 rail、没有横向溢出；此前本轮的桌面与手机页面、草稿预览和控制台检查保持通过；
- 专业验收独立确认：Robotaxi-only published Brief 会同时进入 Practice 与企业经营体系 rail；Practice 保留 Robotaxi scope，Framework 使用无 scope 的全站最新读取。
