# v0.10.0 观察内容发布流水线

## 问题

新增观察必须直接修改 `src/content/siteContent.js`，并与网站产品版本、tag、全站验收和生产发布绑定。候选信息没有稳定结构、来源引用、草稿隔离、直接预览和 content-only 发布边界。

## 实现

- 建立 ObservationPublication → EvidenceUnit → Source 三层内容模型、JSON schema、受控枚举和独立 `content/observations/` 目录；
- 将现有两篇观察无损迁移出 `siteContent.js`，作品、About 和上游事实边界保持不变；
- 建立统一公开读取层和首页查询层，固定最多四条、最多两条 brief、保留 standard/deep 和 `promoteToHome` 规则；
- 继续复用 v0.9.0 ObservationCard / CardGrid，详情页统一为范围与事实、经营影响、层级扩展、证据与边界；
- 建立 candidate import、schema/content check、隔离 draft 直接预览、promote 和 content scope check 命令；
- draft 只存在于被 Git 忽略的 `.content-workspace/`，开发期通过 serve-only 端点读取，生产读取层和 bundle 不包含草稿；
- 保留 matching-tag 的产品版本发布通道，新增不制造 tag、只允许一篇 published observation 的 content-only 发布通道；
- 建立严格 Source URL 合同：外部只允许安全绝对 HTTPS，站内路径只允许 internal snapshot；
- 构建时生成与 release 同版本、同 commit 的 `content-manifest.json`，公网内容验证必须确认目标 slug 实际存在，避免 SPA fallback 假阳性。

## 验证

- `npm run release:check` 通过，43 项测试全部成功；
- `git diff --check` 通过；
- 自动验证覆盖 schema、枚举、重复 slug、sourceRefs、草稿隔离、首页配额、candidate 生命周期、content scope、双发布脚本和迁移事实；
- URL 专项测试覆盖 HTTPS、站内快照、恶意协议、协议相对、裸相对路径、控制字符和错误来源类型；
- 公网验证专项测试证明：目标 slug 存在时通过，未知 slug 即使返回正常 SPA HTML 仍会失败；
- 真实浏览器首次验证覆盖 1440、1024、768、557、520、390、320px 的首页、观察索引、brief、deep、standard draft，以及 Works、About、企业架构和手机菜单；
- 第二次最小回归覆盖 1440/390 的观察索引、deep、brief、standard draft；metadata 无重复、来源链接属性正确、横向溢出为 0、console error/warning 为 0；
- 产品设计 task 已完成结构、视觉、内容流程、草稿隔离和发布安全边界的两轮专业验收。

## 已知边界

- 当前不包含后台、数据库、CMS、账号系统、自动审核或 Scheduled task 直接生产发布；
- content-only 发布仍要求人工审核、独立 Git 提交和明确生产授权；
- `content-manifest.json` 是构建产物，不复制正文或业务事实，也不进入内容提交范围；
- 脱敏 candidate fixture 只用于测试；本地复验草稿在稳定收口前已经清理。
