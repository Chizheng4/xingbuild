# v0.26.0 — 发布内核与 ContentSet 架构重构

## 版本边界

- 父版本：`v0.25.19` / `43ab99bea9b3221c3a912bc66102b6491f024284`
- 正式方案：[`docs/design/v0.26.0 发布内核与 ContentSet 架构重构方案.md`](../../design/v0.26.0%20发布内核与%20ContentSet%20架构重构方案.md)
- 本版本仅重构发布内核与迁移边界；不执行产品或内容 transport，不修改 UI、IA、schema、视觉、正文、审核或媒体事实。

## 实现与不变量

- `ContentSet v1` 覆盖 home、profile、product、article、businessObservation、practice 与 observation，保存 source/review/media proof；唯一 active 指针通过 CAS 原子切换，旧 `contentReleaseId` 只保留为 `legacyAuditId`。Home 首批迁移 description、homeTitle 与 observations empty-state 文案，正文区继续引用各自 entries。
- 一次性迁移对本地 active 与公网 `content-manifest.json` 做双向 identity、集合、目标、hash、路由和媒体核对；冲突硬失败，只导入公网已验证集合，未上线候选不进入 active。
- `ProductArtifact`、`SiteSnapshot`、`PublicationRun` 固化产品身份、整站 snapshot、deployment/传播/publicVerify/resume/rollback；同一个 snapshot 只允许一个 deployment，失败不污染旧 active。
- 兼容入口 `content-release`、`publish-*` 和 product publish 均提交到同一 Coordinator；旧 Registry/receipt/lineage/projection/package 不再作为正常 active 运行时权威。

## 验收边界

完成分层 QA、版本收口、最终 HEAD/tag 构建和 ProductArtifact preflight 后，交由产品/视觉以同一产物独立验收；产品公网完整验证后才恢复 ContentSet Candidate 内容运营。
