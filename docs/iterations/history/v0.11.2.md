# v0.11.2 内容合同测试修订

## 问题

`v0.11.1` 的两条工程测试错误地把当时的公开内容快照写成固定预期：一条断言没有 explicit Brief，另一条断言构建 manifest 只有两条旧 slug。新增合法公开内容时，内容检查和构建正确通过，测试却错误失败，违反 content-only 发布不应要求改工程测试的边界。

## 实现

- Brief 测试改为使用受控 publication 验证：没有 explicit brief 时不推导；显式、合法 brief 可以投影；draft、冗余字段和错误详情路径继续失败。
- manifest 测试从当前 `content/observations/` 读取所有 published ObservationPublication，动态验证构建产物与公开集合一致。

## 验证

- `npm run release:check` 通过，50 项自动测试全部成功；公开集合可从 2 条扩展到 10 条而不改变测试语义；
- `git diff --check` 通过；
- 专业复验确认两条测试均已从内容快照收敛为内容合同。

## 发布边界

- 本版本只包含测试与必要版本/迭代记录；不包含 8 个未追踪 ObservationPublication；
