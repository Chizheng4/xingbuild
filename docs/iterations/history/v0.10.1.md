# v0.10.1 内容导入安全消费补丁

## 问题

`content:import` 成功生成 draft 后仍保留 `.content-workspace/imports/` 输入，而 `publish-content.command` 会正确拒绝任何 workspace JSON。正常内容即使完成 promote，也会被已消费但未清理的 import 阻断，迫使人工删除文件，并产生误删风险。

首条真实 XPENG 草稿同时暴露出桌面标题拆开完整业务词组的问题，需要在不修改全局视觉系统的前提下形成内容级语义换行检查。

## 实现

- 只有输入精确位于当前 content root 的 `.content-workspace/imports/`、文件名与 slug 一致、候选校验通过、无 published/draft 冲突且 draft 通过 `wx` 排他写入成功后，才删除这一条精确 import；
- 外部输入永不删除；无效候选、重复 draft 和写入失败均保留原输入；
- 导入结果明确报告 workspace import 是否已消费；
- 保持生产读取层不扫描 workspace，保持 content-only 发布对残留 workspace JSON 的拒绝；
- 在内容发布规则中固定 1440px 与 390px 的标题业务词组人工检查，仅对真实拆词使用最小 WORD JOINER，不引入自动中文分词；
- XPENG 草稿仅保留在 ignored `.content-workspace/drafts/`，没有进入公开内容集合。

## 验证

- 自动测试覆盖 workspace 成功消费、外部输入保留、无效候选保留、重复 draft 保留和写入失败保留；
- 同一 XPENG 候选完成 import → draft → preview，import 已精确消失，draft 合法且仍为 `draft`；
- 1440×1000 与 390×844 真实浏览器确认“员工测试”四字同一基线、无横向溢出，console error/warning 为 0；
- `npm run content:check` 通过，公开观察仍为两篇；
- `npm run release:check` 通过，46 项测试全部成功；
- `git diff --check` 通过；
- 产品设计 task 已完成结构、视觉、响应式和安全边界专业验收。
