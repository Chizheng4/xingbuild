# v0.12.2 发布就绪状态收口

## 问题

`v0.12.1` 的范围提交与标签正确，但工作区仍保留下一轮规则和设计文件。发布脚本正确拒绝脏工作区，却没有一个可以在发布前快速复用、并与收口报告共享的本地状态合同，导致“已本地收口”被误解为“可发布”。

## 实现

- 新增提交前 `release:closeout-check` 与提交后 `release:preflight`：前者拒绝未暂存或未追踪的跨版本残留；后者要求 `main`、空工作区、`package.json`、`VERSION.md`、当前迭代、HEAD 标签和预期 `origin` 一致。
- 产品发布命令复用该检查；保留原有构建、GitHub、EdgeOne 和公网验证责任，不增加自动暂存、自动恢复或隐式发布行为。
- 将“本地版本完成”与“可发布”写入迭代、发布与项目执行规则，并以纯函数测试锁定失败原因。

## 验证

- 就绪测试覆盖通过状态、脏工作区和标签不匹配。
- `release:check`、`git diff --check` 通过后再创建匹配标签。

## 发布边界

- 本轮不推送、不部署、不修改 DNS。
