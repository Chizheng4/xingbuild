# v0.6.1 对象内部构图节奏修订方案

## 1. 结论

`v0.6.0` 已正确解决栏目级双重留白，但错误地把“对象层级”直接映射成“对象内部统一大间距”。

本轮只修订内容对象内部构图，不推翻六层视觉结构：

```text
v0.6.0
栏目结构与间距责任：正确
对象语义角色：正确
对象内部关系映射：错误
```

根因同时来自设计和实现：

- 设计方案对 `ObjectStack` 默认应使用什么关系说明不足；
- Engineering 将 `.object-stack` 统一映射为 `--rhythm-object`；
- Identity、Proposition、Evidence、Action 虽有语义类名，但每一组之间都被固定为约 48px。

### 4.1 重点观察

| --- | ---: |
| Identity → Proposition | 约 48px |
| Proposition → Evidence | 约 48px |

标题与内容之间缺少紧密归属，作品对象被纵向拉散。

### 4.3 与 Maggie 的差距

Maggie 同类内容通常保持：

```text
标题
↓ 紧密
说明
↓ 紧密
元数据

对象
↓ 明显更疏
下一对象
```

xingbuild v0.6.0 则变成：

```text
元数据
↓ 大
标题
↓ 大
说明
↓ 大
行动
```

差距本质不是 Maggie 数值更小，而是 Maggie 清楚区分“对象内部”与“对象之间”。

## 5. 修订规则

### 5.1 默认关系

- Identity → Proposition：`relate`
- Proposition → Evidence：默认 `relate`
- Evidence → Action：`relate`
- Content Object → 下一 Content Object：`group`
- SectionIntro → SectionBody：`object`
- Section → 下一 Section：`section`

只有当 Evidence 本身形成独立主要分区时，Proposition → Evidence 才升级为 `object`。

### 5.2 ObjectStack

`ObjectStack` 表示对象内部构图责任，不表示所有子项使用 `--rhythm-object`。

最小实现可以是：

- `.object-stack` 默认使用 `--rhythm-relate`；
- 需要更大分区的组件显式声明关系；
- 或由 `.object-identity + .object-proposition` 等稳定的语义相邻关系控制。

推荐优先调整现有布局原语，不增加页面专用选择器。

### 5.3 不做

- 不改变 PageStack、SectionFlow 和 CollectionFlow 已通过的责任；
- 不重做首页 Hero；
- 不更换字体、颜色、版心、导航或内容；
- 不删除 Identity、Proposition、Evidence、Action；
- 不复制 Maggie 的 4px、10px 数值；
- 不给每个页面重新写一套对象间距。

## 6. 目标节奏

桌面建议：

| 关系 | 目标 |
| --- | ---: |
| Identity → Proposition | 16–24px |
| Proposition → Evidence | 20–32px |
| Evidence → Action | 16–24px |
| 对象 → 下一对象 | 48–64px |

手机按现有 fluid token 收敛，但对象内部必须明显小于对象之间。

数值是验收区间，Engineering 必须通过语义 token 实现。
