# v0.5.0 根本视觉构图优化方案

## 1. 方案定位

- 状态：设计完成，交由 Engineering 网站迭代 task 直接实施
- 设计依据：xingbuild 与 Maggie Appleton 首页在 Chrome 浅色模式下的 1440×1000、390×844 对照
- 视觉事实源：`docs/design/xingbuild Visual System v1.md`
- 本轮性质：视觉构图与排版责任升级，不是局部 CSS 修补

`v0.4.0–v0.4.1` 已经建立 Visual System v1、组件与样式责任、响应式导航。本轮不推翻该基础，而是解决真实页面仍然存在的三项结构性问题：

1. 桌面 Hero 的内容起点过低、标题列过窄，页面空间没有被有效利用；
2. 衬线字体承担过多角色，标题、解释、栏目和正文之间缺少清楚分工；
3. 手机端栏目说明与第一项真实内容之间仍有无效空白，辅助说明过弱。

## 2. 根本逻辑

```text
视觉优秀程度
≠ 更多装饰、组件或动效

视觉优秀程度
= 内容对象关系清楚
  × 字体角色有差异
  × 空间表达真实边界
  × 响应式保持同一品牌
  × 工程规则能够稳定复用
```

因此本轮所有修改必须落到既有 token、布局组件和页面编排责任中，不允许通过首页专用 magic number 或连续 media override 形成表面效果。

## 3. 品牌名称合同

唯一品牌写法：

```text
xingbuild
```

- 全小写；
- 拼写固定为 `xingbuild`；
- 不使用 `XingBuild`、`Xingbuild`、`XINGBUILD`；
- 不使用错误拼写 `Xingbulid`；
- wordmark 继续是文字，不增加图形 Logo；
- 页面标题可使用 `xingbuild — 金星 · Xingjin`；
- 作者身份继续属于页面内容，不进入全局页头或页脚。

名称不需要重命名。本轮只增强 wordmark 的字体、字距和稳定尺度。

## 4. 桌面首页结构

### 4.1 当前问题

1440×1000 实测：

- 主标题顶部约 308px；
- 主标题有效宽度约 617px；
- “最新观察”约在 960px 才开始；
- 标题右侧存在大面积没有承担内容关系的空白；
- “运行”发生非语义断行。

### 4.2 目标

- 主标题顶部进入约 160–210px 区间；
- 标题有效宽度进入约 820–940px 区间；
- 中文标题在 1440px 优先形成自然两行，不在词义中间被窄列强制断开；
- 首页第一个 1000px 视口能够看到“最新观察”标题、栏目说明和第一项内容的开始；
- Hero 仍然克制，不增加状态卡、所在地、图片或多余操作。

### 4.3 工程落点

必须通过以下责任实现：

- `HeroStatement` 或等价组件负责内容结构；
- 页面网格负责标题起点和有效列宽；
- `--type-display`、`--measure-display`、`--space-hero` 等语义 token 负责尺度；
- `clamp()` 负责宽度间的连续变化；
- 不在首页 JSX 写内联样式；
- 不用只对 1440px 生效的单点补丁。

## 5. 字体角色

### 5.1 保留衬线

- wordmark；
- 首页核心陈述；
- 页面标题和文章标题；
- 章节标题；
- 长文正文；
- 作品问题陈述和重要作者定位。

### 5.2 改为无衬线

- `金星 · Xingjin` 作者标识；
- Hero 解释文字；
- 栏目说明；
- 日期、主题、内容类型；
- 导航、目录、状态、行动；
- 作品来源、边界和架构辅助文字。

### 5.3 原因

这不是风格混搭，而是建立责任：

```text
衬线：作者判断、长期内容、需要阅读的主体
无衬线：解释、定位、操作、状态和系统信息
```

手机端继续保留衬线标题与长文正文，不允许重新回到“桌面衬线、手机全部无衬线”的分裂模式。

## 6. 手机首页结构

### 6.1 保留

- 390px 主标题约 38px；
- 单列布局；
- 暖白、墨色、赭色品牌；
- wordmark + 菜单；
- 最新观察在首屏进入；
- 520px 以下全屏菜单合同。

### 6.2 调整

- Hero 说明提升到约 16.5–17.5px；
- Hero 说明使用无衬线、行高约 1.75–1.85；
- 缩短栏目说明与第一项观察之间的空白；
- 390×844 至少看到第一项观察的元数据和标题开头；
- “查看全部”不得小于正常可读的操作字号；
- 保持 44×44px 触控目标。

### 6.3 不允许

- 为让内容进入首屏而压缩所有区块；
- 降低元数据字号；
- 隐藏必要摘要；
- 使用负 margin 叠加内容；
- 破坏 557px 紧凑行内导航和 520px 手机菜单边界。

## 7. 空间关系

本轮统一检查并落实：

| 关系 | 目标范围 |
| --- | --- |
| 作者标识 → 主标题 | 12–20px |
| 主标题 → Hero 说明 | 24–32px |
| Hero → 最新观察 | 64–96px 桌面；48–72px 手机 |
| SectionIntro → 第一项内容 | 32–48px |
| 元数据 → 内容标题 | 12–20px |
| 标题 → 摘要 | 12–20px |

判断规则：

- 同一内容对象内部紧密；
- 不同对象之间疏松；
- 留白必须表达对象边界，不为“高级感”制造无意义距离。

## 8. Wordmark

`xingbuild` 的识别度通过文字排版完成：

- 桌面约 28–32px；
- 手机约 24–28px；
- 衬线字形；
- 中等字重；
- 轻微收紧字距；
- 桌面和手机使用同一字体角色；
- 不添加强调色分段、图标或字母解释。

## 9. 页面与组件影响

主要影响：

- 首页 Hero；
- SectionIntro；
- ObservationFeature；
- SiteHeader wordmark；
- 全局 typography 和 spacing token。

回归影响：

- 观察列表；
- 短观察和分析长文；
- 作品列表和作品详情；
- 关于我；
- 557、520、390、320 响应式区间。

本轮不改变：

- 内容对象；
- 路由；
- 一级导航；
- 作品状态和证据边界；
- Robotaxi、career 上游事实；
- Sites 构建和发布结构。

## 10. 验收标准

### 10.1 桌面 1440×1000

- 主标题顶部约 160–210px；
- 标题宽度约 820–940px，并形成自然中文换行；
- 首屏看到最新观察及第一项内容的开始；
- 标题、解释、元数据字体角色清楚；
- 无新增装饰卡片、横线或空状态模块。

### 10.2 手机 390×844

- 主标题保持自然换行；
- Hero 说明清楚但不与标题竞争；
- 首屏看到第一篇重点观察标题的开始；
- 菜单、查看全部、继续阅读等触控目标可用；
- 无横向溢出。

### 10.3 中间宽度

- 1024、768、557、520 不出现标题突然变窄、字体角色突变或导航临界抖动；
- 557px 保持紧凑行内导航；
- 520px 以下进入完整手机菜单；
- 架构图和长文既有行为不回退。

### 10.4 工程

- 调整落在语义 token、既有组件或明确页面编排责任；
- 不新增同义颜色、字号和间距常量；
- 不增加无必要依赖；
- 视觉合同测试覆盖 Hero 尺度、字体角色和导航断点；
- `npm run release:check` 通过；
- 完成真实 Chrome 浅色模式视觉 QA；
- 保留固定浅色主题，不自动跟随系统暗色。

## 11. 执行与成本边界

Engineering task 接手后：

1. 先识别现有 `v0.4.1` 与本方案的真实差异；
2. 给出一次简洁文件级计划后直接执行，不等待确认；
3. 优先修改已有 token 和组件，不重建体系；
4. 只验证受影响页面和必要回归路径；
5. 不重复进行无关浏览器审视；
6. 稳定后形成下一个版本提交和标签；
7. 不推送、不发布，除非用户在 Engineering task 明确授权。
