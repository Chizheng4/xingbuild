# v0.24.16 内容运营独立合同与 B 端内容协作方案

> 状态：已确认正式方案
> 目标：修正内容运营与产品工程版本的责任混合，并为 B 端产品页面内容协作提供唯一入口。
> 事实源：`docs/product/xingbuild 网站产品架构与视觉系统总案.md`、`docs/operations/内容运营与发布规则.md`

## 1. 目标

- 内容运营独立负责事实审核、内容结构、用户确认、内容发布和公网内容验收。
- 产品与 Engineering 独立负责页面结构、IA、schema、组件、交互和工程能力版本。
- B 端产品页面增加已批准内容时，不自动启动产品工程版本；只有页面能力或对象边界改变时才进入产品版本。
- xAI CLI 页面只作为信息组织与表达节奏的研究对象，不复制其文案、素材或业务事实。

## 2. 两条工作流

```text
产品工程：产品方案/current → Engineering → v0.x commit/tag → 产品视觉验收 → 用户授权 publish
内容运营：事实/来源 → Draft → 用户确认 → 内容发布包 → 内容发布 → 公网内容验收
```

内容只在发现现有页面结构、schema、交互或能力不足时回报产品与视觉 task；不得在内容流程中自行改代码或创建产品版本。

## 3. B 端页面内容合同

当前 B 端产品是 `/products` 的 Robotaxi 运营平台，复用既有 `ShowcaseLayout`、`PracticePage`、`SystemStage`、批准媒体和 Observation rail。

内容 task 只维护：

- 标题、简介、事实边界；
- 产品能力模块的标签、说明、证据和行动入口；
- 已批准媒体的选择与来源说明；
- 页面阅读顺序、模块结论和 CTA。

内容 task 不维护：

- 路由、页面组合、组件、CSS、schema 和交互能力；
- 产品工程 `current.md`、`VERSION.md`、产品 history、commit 或 tag；
- 未确认的产品候选或工程实现。

## 4. 版本与发布边界

- 产品版本使用 `v0.x`，由 Engineering 创建并由产品/视觉验收。
- 内容发布使用独立内容发布身份（内容批次、hash、目标 slug、来源、审核和公网证据），不递增产品版本。
- 内容发布不得修改产品版本文件、创建产品 tag、调用产品 `release:preflight` 或声称产品版本已更新。
- 产品结构和能力仍使用统一产品版本发布；内容发布能力的工程改动本身属于本版本 v0.24.16 的 Engineering 实施范围。
- 在内容独立发布能力完成前，内容 task 可以继续完成内容确认和本地预览，但必须报告“独立发布能力尚未完成”，不得发布或伪称独立上线。

## 5. 验收

- 规则入口、产品总案、Agent 入口和 README 不再出现相互矛盾的内容版本表述。
- 内容 task 可读取本方案与运营规则，直接理解网站页面能力和 xAI CLI 参考边界。
- 内容准备不会修改产品版本身份；产品能力修改仍被产品版本门禁阻断。
- Engineering 完成内容独立发布实现后，内容失败只保留内容 draft/review/recovery 和故障证据，不写产品完成历史。
