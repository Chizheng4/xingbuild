## 1. 版本目标

本版本只解决一个问题：让“企业经营体系”从文章中的一张静态图，升级为可阅读、可下钻、可返回的多视图架构能力；读者能够先理解整体，再按层级进入局部，而不再面对一张拥挤、粒度混杂、线条不可读的巨图。

这不是重做网站结构，也不是新增一个与文章无关的页面。它是 `RichDocument` 中一种可声明的架构能力投影：文章继续负责解释，架构浏览器负责结构阅读，两者使用同一事实模型和稳定入口。

## 2. 事实源与边界

- 企业经营体系的概念、节点、关系、定义和作用，继续以 career 已确认框架及 xingbuild 的批准同步快照为准；Engineering 不得自行改写、补造或重新解释事实。
- `frameworkModel`/批准快照是语义事实源；LikeC4 `.c4` 只是架构视图的可编辑表达源，必须能追溯到语义源，不能成为第二份业务事实模型。
- 当前公开文章对象为 `content/articles/enterprise-operating-system.json`，文章正文、目录、caption 和入口由内容对象声明；内容 task 不写组件 JSX、节点坐标、SVG path 或视口专用 CSS。
- 本版本不读取、嵌入或改动 Robotaxi 仓库、Robotaxi 运行状态、登录态、访问记录或独立站；Robotaxi 不是本版本的事实或工程依赖。

## 3. 读者产品结构

```text
企业经营体系长文（RichDocument）
├─ 正文：概念、经营含义与闭环解释
├─ 文章内局部图：只回答当前章节的一个问题
└─ 架构视图入口：打开同源的多视图阅读空间
   ├─ Landscape：企业经营体系总览
   ├─ Business：企业业务架构
   ├─ Digital：数字化实现
   └─ Product：B 端产品架构（其下层不在本版本继续下钻）
```

架构视图是文章中的一种 `VisualizationHost`/`CapabilityComposition` 内容能力，不另建一套页面产品结构。进入、返回、锚点和刷新必须保持真实上层关系；旧 `?view=digital-implementation` 链接继续安全降级到文章稳定锚点。

## 4. 多视图与模型合同

### 4.1 视图原则

- 每个视图只表达一个抽象层级和一个读者问题；总览不塞入所有下层节点。
- 可下钻节点显式声明目标视图；视图标题、面包屑/返回目标和当前焦点始终可见。
- 企业、业务能力、系统、组件、操作、结果和反馈不能在同一层作为同类卡片；关系类型必须有语义名称。
- 只使用批准模型中的节点和关系；不为了填满画布增加空卡片、内部 slug 或无意义的线。

### 4.2 LikeC4 责任

LikeC4 是本版本的架构模型与多视图运行时 adapter，负责边界、类型、关系标签、视图导航和只读交互。不得退化为把 LikeC4/Graphviz 输出当作一张无语义 SVG 再自行重画。

Engineering 可以采用锁定版本的官方 LikeC4 runtime/CLI 与其受控渲染能力；不要求手工声明节点坐标或路径。若某一视图在移动端无法保持可读，必须使用该视图的分层/文本投影，而不是把桌面图缩成缩略图。

### 4.3 文章局部图的责任

文章内 `figure` 继续只回答局部问题，使用现有 source-driven figure/锁定 adapter；不在文章正文中重复实现完整多视图交互。图下只保留一个“打开架构视图”的同源入口，失败时显示同源标题、关系清单和正文链接。

## 5. 交互与视觉合同

### 桌面（1440/1024）

- 架构浏览器位于文章能力空间内，使用现有暖色编辑式视觉和字体角色；不引入深色模式、品牌换肤或新的全站导航。
- 视图导航、返回、平移/缩放/复位（若由 LikeC4 runtime 提供）位于能力空间内部；不增加页面级工具栏，不改变文章主标题和右侧 Observation rail。
- 节点 hover、focus、click 只改变强调色、边界或关联关系的可见层级，不移动节点、不重排视图、不让关系线突然消失；点击/Enter/Space 的语义一致。

### 紧凑宽度（768/557）

- 保留视图标题、当前层级和可操作节点；控制密度下降但不改变模型关系。
- 视图在可用空间内自然缩放或切换为分层阅读；不得出现横向页面溢出、节点/标签相互遮挡或被文章组件边缘裁切。

### 手机（390/320）

- 不把完整桌面总览压缩成不可读缩略图；优先显示当前视图、可触控节点和关系清单/文本降级。
- 节点点击/tap、键盘焦点（适用时）和返回均保持语义；图形失败时仍能从关系清单和文章正文理解结构。
- 页面自然纵向滚动，能力空间与正文有明确间隔；无横向溢出、无滚动锁死、无布局晃动。

### 统一可访问性与失败边界

- 所有可进入节点都有可见 focus-visible、键盘等价操作、中文名称和读者可理解的状态提示。
- runtime/模型/资源失败不得复用旧图、显示空白画布或伪装成功；必须显示同源的文本/关系清单和返回文章入口。
- 公开 DOM 不显示治理标签、内部 ID、来源等级或未公开上游状态。

## 6. 内容与运营影响

- 既有 Observation Brief、Article 内容审核、slug 级内容发布和 Practice 独立发布合同不变。
- v0.22.0 完成后，新增企业经营体系章节、caption、来源和已支持的局部图仍由内容 task 通过 article 发布，不改产品版本。
- 只有新增视图类型、改变模型层级、增加新 renderer、改变架构运行时或公共 fallback 合同，才重新进入产品版本。
- 内容 task 不负责维护 LikeC4 运行时；若要增加节点/关系，必须引用已确认的语义事实并走产品/视觉事实审核。

## 7. 工程最小交付

Engineering 只实现以下合同，不扩展为通用“全能力平台”：

1. 为企业经营体系提供一个受控、只读的 LikeC4 多视图能力投影，并由文章内容声明入口。
2. 实现 Landscape、Business、Digital、Product 四个视图及其明确进入/返回关系；不增加 Robotaxi、组件级或未确认视图。
3. 保留当前文章、目录、Observation rail、Header/Footer、旧链接降级和内容发布边界。
4. 视图模型由批准语义源生成/校验，生成失败硬失败，不复用旧产物；公开运行时提供文本降级。
5. 不在 JSX/CSS 中写节点坐标、关系 path、视口专用业务文案或页面私有 renderer 分支。

## 8. 验收合同

### 产品验收

- 首屏文章仍能解释企业经营体系；架构入口明确且只出现一次。
- 四个视图的抽象层级、节点粒度、边界、关系标签和进入/返回语义一致；不存在内部 ID、空卡片或混层关系。
- 从文章进入任一视图、从视图返回文章、刷新、直接访问旧链接和浏览器历史均成立；返回焦点恢复到原入口。

### 视觉/响应式验收

- 1440、1024、768、557、390、320 六档真实渲染：无横向溢出、无裁切、无节点/标签互撞、无 console error/warning。
- 桌面和紧凑宽度可辨识边界与关系方向；手机保持分层/文本阅读，不以缩小桌面图冒充适配。
- hover/focus/click/tap 不产生明显晃动、重排、线条消失或页面跳位；键盘 Enter/Space 与触控路径可用。

### 工程/来源验收

- LikeC4 validate/codegen/runtime 专项通过；生成物具有来源 hash/版本记录，失败先清理旧产物。
- 全量 `npm run release:check` 通过，构建不改变 Observation 数量或内容发布对象。
- 公开页面不读取 `.content-workspace`，不泄露治理字段；内容与产品提交范围严格分离。

## 9. 明确不做与后续队列

本版本不做：`CapabilityHost` 全部 renderer 注册平台、Robotaxi `/embed`、动态登录/系统操作、Mermaid/D2 新 adapter、B 端产品主页重构、Observation schema/短文改造、全站主题切换、任意页面专用图形控件。

`XBUILD-CAPABILITY-001` 继续留在 `docs/iterations/candidates/`，待本版本真实使用证明需要统一能力展示控件后再单独立项；不得因本版本实现而自动进入 Engineering。
