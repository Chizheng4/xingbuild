# v0.13.0 信息架构、展示母版与富文本内容系统方案

## 0. 结论与执行边界

v0.13.0 是一次性“结构系统收口”，不是继续用 CSS 修补当前页面。它固定：

1. 一级信息架构与页面责任；
2. 首页、B端产品、经营观察的内容投影关系；
3. B端产品与经营观察共用的 `ShowcaseLayout`；
4. 观察信息块、集中观察页与长文的层级和返回关系；
5. `RichDocument` 的富文本对象、字号和相邻间距；
6. 作品媒体、观察、长文、关于我及认知框架的纯内容入口。

完成并验收后，日常新增产品模块、批准媒体、观察、长文、关于我内容和已确认的认知框架快照，只走内容校验、预览、审核和 content-only 发布，不再成为网站产品迭代。只有新增内容对象类型、页面层级、布局规则、交互能力或媒体类型时，才进入新的产品迭代。

本方案不修改 career 的权威事实，不改写企业经营体系概念，不伪造 Robotaxi 场景、媒体、深链或经营结果。

## 2. 信息架构与路由

### 2.1 一级结构

```text
xingbuild
├─ 首页 /
├─ B端产品 /products
│  └─ Robotaxi运营平台
├─ 经营观察 /business-observations
│  ├─ 企业经营体系
│  ├─ 观察信息块
│  └─ 长文
├─ 关于我 /about
└─ 集中观察页 /observations
```

公开产品名固定为 `Robotaxi运营平台`。“经营闭环模拟”可以出现在事实准确的能力说明中，不能替代产品名称。

旧 `/robotaxi`、`/enterprise-operating-framework`、`/works` 及历史详情地址保留兼容跳转，但不进入新导航。

### 2.2 Header

- 桌面建议高度 56px，手机 52px；
- `position: sticky; top: 0`，所有一级页面、集中观察页与长文共用；
- 暖白背景保持品牌一致；滚动后只允许极轻的背景层次或低对比阴影，不使用明显分割线；
- Header 不能在滚动时动态跳变高度；
- 手机全屏导航从 Header 下方开始，打开时锁定页面滚动并保留关闭按钮。

### 2.3 Footer

固定显示：

```text
© 2026 xingbuild · v0.13.0
```

- 11–12px muted；
- 产品版本来自唯一构建版本事实源，不在页面内容中手写；
- content-only 发布不改变产品版本；
- 不加入作者、地点、更新时间或状态说明。

## 3. 首页：只投影正式内容

首页不是独立内容系统：

```text
全宽定位语（唯一 H1）

┌──────────────────────── 主内容 ───────────────────────┐  ┌─ 最新观察 Rail ─┐
│ 最新B端产品                                            │  │                  │
│ 复用 B端产品查询结果第 1 个 ShowcaseObject             │  │ 同一数据与同一块 │
│                                                       │  │                  │
│ 最新经营观察                                           │  │ 首页只出现一次   │
│ 复用经营观察查询结果第 1 个 ShowcaseObject             │  │                  │
└───────────────────────────────────────────────────────┘  └──────────────────┘
```

### 3.1 定位语

首页唯一 H1：

> 我对企业如何经营、学习和演进充满好奇，也持续探索如何通过 B 端产品、数据与 AI，让复杂的经营问题变得更清楚、更可行动。

- desktop 26–28px / 1.45，mobile 21–22px / 1.52；
- 最大文本宽 720px，但定位语所在 section 占完整 shell；
- Header → H1：desktop 32px，mobile 24px；
- 删除可见“首页”“核心实践”和小号 `PositioningStrip` 投影。

### 3.2 首页复用

- “最新B端产品”当前直接渲染 `Robotaxi运营平台` 的完整 `ShowcaseObject`；
- “最新经营观察”当前直接渲染 `企业经营体系` 的完整 `ShowcaseObject`；
- 首页不得复制标题、说明、媒体、选中状态或关系定义；
- 首页只查询 `isLatest=true` / 排序后的首对象；
- 首页 Rail 只出现一次，后续“最新经营观察”不再复制 Rail。

## 4. B端产品与经营观察：同一 ShowcaseLayout

两页只有内容集合不同，页面结构、几何、标题层级、交互与响应式完全一致。

### 4.1 桌面几何

在 1280px shell 内：

```text
┌────────────────── 主展示区 952px ──────────────────┐ 24px ┌ Rail 304px ┐
│ explanation 208px │ 20px │ SystemStage 724px       │      │ Observation │
│ 标题 + 极短说明    │      │ 约 16:10，视觉主角       │      │ Blocks      │
│ 垂直居中           │      │                         │      │             │
└─────────────────────────────────────────────────────┘      └─────────────┘
```

- 页面 shell：max 1280px；desktop gutter 至少 32px；
- 主区与 Rail：24px；
- Rail：固定 304px，不随大屏膨胀；
- 主区内部：说明列 208px、间距 20px、视觉列占余宽；
- 说明列与 SystemStage 同高，说明在垂直方向居中；
- 只有当 SystemStage 仍可保持至少 640px 有效宽时才启用整页双栏；否则转为单列；
- 单列时主内容在前、观察流在后；SystemStage 在说明之前显示；
- 手机 gutter 20px，≤360px 为 16px。

### 4.2 ShowcaseObject

固定字段：

```text
id
section
title
shortDescription
stage
action?
statusBoundary?
sortOrder
isLatest
```

固定视觉结构：

```text
左：title → shortDescription
右：SystemStage
```

- 不显示装饰序号；
- 不显示数据分组标题；
- 不显示内部 loopRelation；
- `statusBoundary` 只在读者必须知道、否则会产生事实误解时显示；
- 相同对象在首页和栏目页使用相同组件、字段、顺序与媒体。

### 4.3 B端产品

当前集合只有 `Robotaxi运营平台`。首批四项内容继续沿用批准媒体与事实边界，但：

- “运营中控台”保留为内容分组，不渲染额外可见标题；
- 删除公开红色 loopRelation；
- SystemStage 是页面主角，说明只承担识别与必要边界；
- 后续增加模块只增加内容对象和 approved media，不改组件。

### 4.4 SystemStage

统一允许：

```text
image | video | controlled-system | framework
```

共同合同：

- 固定视觉槽位，desktop 默认 16:10；
- 静态图片使用 contain，不裁掉系统主导航或关键界面；
- 视频必须有 poster、字幕/文字替代和暂停控制；
- 受控系统页面必须由上游提供稳定公开场景，不能由 xingbuild 注入假数据；
- 有 action 时整块有克制 hover/focus；无 action 时不得伪装可点击；
- hover 只改变表面/边界对比，不上浮、不使用强阴影。

Robotaxi 受控场景必须明确：

```text
showcaseScenarioId
route
view
selectedObject
panelState
navigationState
version
fallbackMediaId
```

刷新后恢复同一默认场景；系统主导航必须可见。当前没有稳定受控场景的模块继续使用已批准图片/视频，不用截图专用假状态。

手机若无法保证系统页面可读，则使用批准预览，整块打开独立 Robotaxi 系统；不是把桌面页面缩到不可读。

### 4.5 经营观察与企业经营体系

企业经营体系是经营观察的首个 `ShowcaseObject`：

- 右侧 SystemStage 为同源 `frameworkModel` 的 GraphCanvas；
- 左侧显示当前节点的固定概念说明；
- 说明只允许读取：概念名称、权威定义、在框架中的作用、直接固定关系；
- career 认知框架及同步后的 frameworkModel 是唯一事实源；
- 网站与 AI 不得概括、润色、缩写或补写概念；
- 缺少权威说明时显示克制空态；
- 节点选择、hover/focus、键盘、平移、复位、刷新默认节点与几何检查保留；
- 删除图下 ExplanationPanel；选中节点后左列原位更新；
- 总览进入局部 view 继续复用同一模型，不建立新的概念事实副本。

## 5. ObservationBlock：短观察与长文入口的唯一信息块

### 5.1 固定 anatomy

普通 Brief：

```text
IIHS对Waymo的安全研究 · 2026-07-23
#安全与事件
80–160 个中文等价字符的事实正文，2–3句，一个段落。
来源：IIHS
```

有长文：

```text
主体 · 日期
#维度
Brief 正文

ArticlePreview
  长文标题
  明确编写的导语/正文预览

来源：……
```

字段责任：

```text
id
eventAt
subject
primaryDimension
body
isOpinion
sourceRefs
primaryTarget
articlePreview?
```

`articlePreview`：

```text
articleId
title
excerpt
href
```

### 5.2 内容长度

- subject：最大 16 个全角等价字符，ASCII 按半个字符计；
- identity：`subject · eventAt`，必须在 320px 单行显示；
- body：最少 80、最多 160 个中文等价字符；
- body：建议 2–3句，只允许一个段落；
- body 至少包含事件、主体/范围/数字，以及必要限定或经营含义；
- 少于 80 视为信息被压缩过度，校验失败；
- 超过 160 或需要背景、比较、因果和论证时，增加长文，不继续拉长 Brief；
- 组件和自动化不得自动截断、拼接或扩写正文。

### 5.3 字体与相邻间距

| 角色 | desktop / mobile | 到下一角色 |
| --- | --- | ---: |
| identity | 12px / 18px UI | 4px |
| dimension | 12px / 18px UI muted | 6px |
| body | rail 15px / 1.70；collection 16px / 1.72 | 8px |
| ArticlePreview title | 16px / 1.5 | 6px |
| ArticlePreview excerpt | 14–15px / 1.65 | 8px |
| sources | 12px / 18px UI muted | — |

### 5.4 视觉与交互

使用 quiet information tile，不使用横线 Feed 或重卡片：

- 暖色表面，比 canvas 深约 3%；
- 圆角 6px；
- collection padding 16px，rail padding 12px；
- collection gap 12px，rail gap 8px；
- 无边框、无阴影、无上浮；
- hover 时表面再加深约 2%，focus-visible 使用统一 2px 强调轮廓；
- 来源默认与“来源：”同为 muted；只在 hover/focus 下出现下划线与品牌强调色；
- 红色只用于当前导航、节点选择和焦点，不用于来源或装饰关系。

交互责任：

- 普通 Brief 的 `primaryTarget` 是批准的主来源；
- 有长文时 `primaryTarget` 是长文；
- ArticlePreview 始终打开长文；
- 来源行保留所有独立来源链接；
- 工程实现不得嵌套 `<a>`；使用一个可访问的主链接层与独立来源链接层；
- 无合法 target 时保持静态 tile，不伪装可点击。

### 5.5 维度

- `#维度` 消费唯一 `ObservationDimensionRegistry`；
- 当前只是非链接分类文本；
- 内容规模形成真实过滤价值后，才升级为 `/observations?dimension=...`；
- 一条 Brief 只有一个主维度；
- Article 可以有多个维度，但使用同一 registry。

## 6. 集中观察页、长文与返回层级

### 6.1 页面层级

```text
第一层：首页 / B端产品 / 经营观察
  ├─ 点击“更多观察”
  │    → 第二层：集中观察页
  │         → 点击有长文的信息块
  │              → 第三层：长文页
  └─ 直接点击有长文的信息块
       → 第三层：长文页
```

普通 Brief 不创建详情页。

### 6.2 返回合同

- 第一层直接进入长文：长文返回原第一层；
- 集中观察页进入长文：长文返回集中观察页；
- 集中观察页再返回：回到触发“更多观察”的第一层；
- 长文始终提供“经营观察”栏目入口，可直接回第一层经营观察；
- 返回关系不能只依赖 `history.back()`；
- 使用经过安全校验的站内 `origin` / `returnTo` 上下文，刷新后仍成立；
- 直接访问集中观察页或长文而没有上下文时，默认返回经营观察；
- 拒绝外部 URL、协议相对 URL 或任意重定向。

### 6.3 宽度

集中观察页、Article 和 About 共用：

```text
ReadingShell max-width: 736px
desktop 居中
mobile gutter: 20px
narrow gutter: 16px
```

页面不得各自设置不同阅读宽度、左偏移或私有 gutter。

## 7. RichDocument：文字和富文本的固定结构

### 7.1 允许的内容块

```text
lead
heading(level 2|3)
paragraph
list
definitionList
figure
callout
sources
```

- Article 与 About 必须消费同一个 `RichDocument`；
- 页面组件只负责页面编排，不直接写正文 JSX；
- 内容块通过 schema 校验；
- 不允许页面自造标题、红色标签、私有卡片、任意 margin 或内容专用 CSS。

### 7.2 字体

| 角色 | desktop | mobile |
| --- | --- | --- |
| 首页定位语 | 26–28px / 1.45 | 21–22px / 1.52 |
| Page H1 | 30–32px / 1.35 | 26–28px / 1.40 |
| H2 | 22–24px / 1.45 | 20–22px / 1.45 |
| H3 / 对象标题 | 18–20px / 1.50 | 18px / 1.50 |
| lead | 16–17px / 1.72 | 16px / 1.70 |
| paragraph/list | 16–17px / 1.85 | 16px / 1.80 |
| caption/sources | 12px / 18px | 12px / 18px |

### 7.3 相邻关系

| 相邻关系 | desktop | mobile |
| --- | ---: | ---: |
| H1 → lead | 12px | 12px |
| lead → 首个 H2 | 32px | 28px |
| H2 → paragraph/list | 12px | 10px |
| H3 → paragraph/list | 8px | 8px |
| paragraph → paragraph | 14px | 12px |
| paragraph ↔ list/definitionList | 16px | 14px |
| section → section | 40px | 32px |
| figure → caption | 8px | 8px |
| body → sources | 16px | 14px |

共同父级拥有兄弟间距；子内容块只拥有内部构图，避免双 margin、margin collapse 和大面积无意义留白。

### 7.4 Article

固定顺序：

```text
返回上一层 / 经营观察
标题
#维度
摘要
RichDocument 正文
来源
```

- 一个 canonical title；
- 不显示 claimKind、sourceTier、事实/分析/企业表述、证据边界等内部治理 UI；
- 摘要是文章导语，不与 Brief 正文混用；
- 来源是正文最后一个 block。

### 7.5 About

- 继续以 career 为事实源；
- 定位、能力、项目、经历、方向、联系映射为 RichDocument blocks；
- 能力/项目优先使用 `definitionList` / `figure`；
- 职业经历使用明确的时间、职责和成果对象；
- 本轮建立内容入口和投影，不擅自改写 career 权威事实。

## 8. 内容入口与“以后不迭代”合同

### 8.1 内容目录责任

Engineering 应建立或收口这些受控内容入口：

```text
content/products/*
content/business-observations/*
content/observations/*
content/articles/*
content/profile/*
content/media/*
content/framework/*
```

具体文件组织可根据现仓库最小演进决定，但必须满足：

- 页面不从 JSX 定义业务内容；
- 首页只通过 query 投影最新对象；
- B端产品和经营观察只通过相同 repository/query + ShowcaseObject 渲染；
- approved media、action、provenance 继续分离；
- 观察继续保留 Publication → EvidenceUnit → Source 治理模型；
- 公开 Brief/Article 只是读者投影，不删除底层证据；
- framework 固定概念只从同步快照读取。

### 8.2 内容更新

以下行为在结构验收后只属于 content-only：

- 增加/调整 B端产品模块；
- 更换 approved 图片、视频或受控系统场景；
- 增加 ObservationBlock；
- 为 ObservationBlock 增加 ArticlePreview/Article；
- 更新 Article、About 或固定框架概念快照；
- 更新来源、日期、正文和排序；
- 改变哪个对象为 latest。

内容更新必须通过各自 schema、预览、人工审核、范围检查、构建和公网验证，但不改变产品版本。

### 8.3 产品迭代

只有这些变化需要新网站迭代：

- 新增内容对象类型或字段责任；
- 改变一级页面、页面层级或返回模型；
- 改变 Showcase/Observation/RichDocument 的统一结构；
- 新增媒体种类、筛选、搜索、嵌入或框架交互能力；
- 当前结构无法诚实表达新内容。

## 10. 验收合同

### 10.1 结构

- 一级导航严格为三项；
- 企业经营体系只属于经营观察；
- 首页两个 latest 对象与栏目页使用同一 DOM/组件和内容源；
- B端产品与经营观察使用同一 ShowcaseLayout；
- 集中观察页不是一级导航；
- Article/About 共用 RichDocument；
- 无页面私有业务内容副本。

### 10.2 视觉

- 1440px：1280 shell、952/24/304 外部几何、208/20/724 内部几何；
- Header sticky 且 ≤56px；
- 视觉/系统列明显大于说明列；
- 页面无 48px 双重横向空洞；
- ObservationBlock 有轻表面、无 border/shadow/lift；
- 来源默认 muted；
- 红色只用于明确状态与焦点；
- About/Article/Observations 左右边界一致。

### 10.3 响应式

真实浏览器至少验证：

```text
1440×1000
1280×800
1024×768
768×1024
557×816
390×844
320×568
```

- 无整页横向滚动；
- identity 在 320px 单行；
- SystemStage 不裁关键 UI；
- 手机媒体在说明前；
- sticky Header 不遮挡锚点、菜单或返回控件；
- observation rail 单列后顺序正确；
- 长文返回上下文刷新后仍正确。

### 10.4 内容与可访问性

- Brief subject/body 长度在 schema 与真实渲染均通过；
- Framework 概念逐项与权威模型一致；
- 主链接与来源链接不形成嵌套 anchor；
- hover、focus-visible、Enter、Space、Escape 和 reduced-motion 合同成立；
- SystemStage 有 alt/poster/fallback；
- console error/warning 为 0；
- `npm run release:check`、`git diff --check` 通过。
