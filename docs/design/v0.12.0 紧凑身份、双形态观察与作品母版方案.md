# v0.12.0 紧凑身份、双形态观察与作品母版方案

## 结论

本轮不是给现有页面再加样式，而是收敛四个长期契约：

1. `xingbuild` 与 `金星 Xingjin` 组成一个紧凑横向身份组；作者署名不是第二行、不是分隔符，也不制造新的空白带。
2. 网站首页恢复为作者入口，`/robotaxi` 是独立作品页；定位语只在首页承担“我是谁”的责任，不能夹在 Robotaxi 标题前充当栏目说明。
3. 作品页左栏固定为两段：**作品说明** 与 **真实视觉证据/架构图**；右栏固定为同一观察流的有限投影。
4. 观察只有两种读者形态：**简讯** 与 **文章**。内容的证据复杂程度不是第三种页面形态。

本轮完成后，Robotaxi 模块、框架局部视图、日常观察均只增加受控内容对象；除非内容模型不能表达新对象，否则不再重做页面、组件或视觉系统。

## 1. 页面与路由责任

| 路径 | 读者任务 | 页面主栏 | 右栏 |
| --- | --- | --- | --- |
| `/` | 认识作者与进入两项核心实践 | 定位语 + 两项核心实践入口 | 最新观察投影（有内容才出现） |
| `/robotaxi` | 理解 Robotaxi 经营模拟作品 | 作品说明 + 真实平台视觉证据 | 最新观察投影 |
| `/enterprise-operating-framework` | 理解企业经营体系 | 作品说明 + 一张可操作总览图 | 最新观察投影 |
| `/observations` | 快速扫读全部公开内容 | 居中单列内容流 | 无 |
| `/observations/:slug` | 阅读确有解释责任的长文 | 文章 | 无 |
| `/about` | 了解作者背景与职业事实 | 原有正文 | 无 |

`/` 不再与 `/robotaxi` 复用同一页。首页不是大 Hero，也不是 Robotaxi 的重复版：它只承担作者定位和两个实践入口。主导航首项仍为 Robotaxi 运营平台；首页没有伪造的“当前栏目”状态。

## 2. 全局身份与页首

### 2.1 身份组

视觉文字固定为：

```text
xingbuild  金星 Xingjin
```

- `xingbuild` 是主标识：桌面 28–30px、Georgia/现有 wordmark 字体、500、紧凑字距。
- `金星 Xingjin` 是作者署名：桌面 11–12px、UI 字体、500、正文墨色的 72–78% 明度。
- 两者同一基线对齐，间距 **8px**（允许响应式在 6–10px 内变化），没有红点、竖线、@、边框或第二行。
- 桌面 header 固定 72px；手机 64px。作者署名在 320px 仍保留，字号降至 10–11px，而不是用双行换取空间。
- 导航与完整身份组垂直居中对齐；header 不得为作者署名增加额外上下 padding。

### 2.2 定位语

定位语是首页的唯一主叙述，不是每个页面重复的 eyebrow，也不是 Robotaxi 的前置说明。

- `/`：定位语置于首页主栏第一对象，18–20px、1.58–1.68 行高、最大阅读宽 680px；距 header 下缘 32px，距实践入口 32px。
- 作品页与观察页不显示该语；它们直接从页面标题或内容流开始。
- 不使用 display hero、超大字或独占一屏留白。定位语最多占两至三行，并由后续真实内容立即承接。

## 3. 空间与布局令牌

所有页面只允许通过下列关系令牌获得空间；页面组件不得自行扩大空白。

| 关系 | Desktop | Mobile |
| --- | ---: | ---: |
| shell 最大宽 / 外侧 gutter | 1280px / ≥32px | 100% / 20px，≤360px 为16px |
| header 高度 | 72px | 64px |
| 双栏主栏 / 间距 / 右栏 | 剩余宽 / **48px** / 320px | 单列 |
| 页首到第一真实对象 | 32px | 24px |
| 主栏两段（说明 → 视觉） | 40px | 32px |
| 视觉模块之间 | 48px | 32px |
| 简讯之间 | 20px | 16px |
| 简讯内部（元信息 → 维度 → 正文 → 来源） | 6px / 8px / 8px | 相同 |

双栏只在 `主栏 ≥ 600px + 48px + 320px` 同时可容纳时成立；否则切为单列。移动端右栏排在主内容之后，间距 40px。

右栏不能由屏幕剩余宽度拉大；它的高度预算为 `min(左栏真实高度, 2 × viewport height)`，只显示完整内容对象和“更多观察”，不裁切半条简讯。无公开内容时，整个右栏不渲染。

## 4. 作品页：左栏的两段母版

### 4.1 第一段：作品说明

每件作品只有一个页面标题，随后是一段短而有对象边界的说明：

```text
作品标题
它解决的经营问题与构建对象（1–2句）
当前证明范围 / 不证明什么（1句，克制显示）
```

这不是“标题—多段文章”的开场，也不显示红色分类、编号、重复副标题或 CTA。

### 4.2 第二段：视觉证据

第二段表达作品真正的系统，而不是装饰图。

- **Robotaxi**：以后每个模块均为同一对象：左侧极短说明（模块负责什么、与经营闭环的关系），右侧真实 16:10 平台截图；桌面永远左文右图，手机永远图上文下。没有获得真实媒体和具体深链时，模块不渲染。
- **企业经营体系**：一张 16:10 的总览 GraphCanvas；图下同宽 ExplanationPanel 解释当前选中节点和直接关系。它仍保留 hover/focus 预览、点击/键盘选中、有限平移、reset 和无障碍状态；局部视图以后只由同一模型的已确认节点入口进入。
- 图框、图内文字、线条与节点必须共享几何验证：不重叠、不压字、不截断、边只落在真实节点边界、关系标签只贴对应线段。

右栏的观察不是另一套“资讯卡片”，而是和观察页相同数据对象的紧凑投影。

## 5. 观察：只保留两种内容形态

### 5.1 简讯 Brief

简讯是事件本身，不是被缩短的文章；默认不点击进入第二页。

```text
2026-07-23 · IIHS / Waymo
#安全与事件
IIHS 研究称……
来源：IIHS
```

- 第一行：`eventAt · 明确主体`；主体只写公司、机构或地区，不把事件摘要伪装成标题。
- 第二行：小号 `#维度`；`观点` 只在确实可能把作者判断误读为客观事实时追加为 `#观点`。
- 第三行：事实正文，直接使用人工审核的 `statement`，无“摘要”“继续阅读”“事实”等解释词。
- 最后一行：`来源：` 后为一个或多个可点击来源名。该行是所有简讯的必需字段。
- 无边框卡片、无大字标题、无 CTA、无独立详情路由。hover 仅轻微改变文字色或来源下划线；焦点清楚但不产生卡片浮起效果。

### 5.2 文章 Article

文章只在内容确实需要背景、比较、因果分析或作者论证时存在独立路由。

```text
文章标题
#准入与政策  #安全与事件
摘要
正文
来源：NHTSA · IIHS
```

- 标题是唯一标题：集合预览、页面标题、浏览器标题均取同一字段，禁止短流一个标题、详情另一个标题。
- 维度紧贴标题下方，使用克制的文字 hashtag，不做彩色标签块。
- 摘要位于维度后；正文采用普通阅读节奏。不要显示 `事实概览`、`经营影响`、`证据与边界`、claimKind、来源层级等内部治理标题。
- 事实限定、媒体归属和作者判断在自然语言中诚实表达；来源统一在文章最后一行。

### 5.3 数据与工程合同

展示模式不是 `level`、`nature` 或 `claimKind` 的投影。新增一个受 schema 校验的显式字段：

```text
presentation: "brief" | "article"
```

- `brief` 必须有 `eventAt`、`brief.subject`、`brief.statement`、`brief.sourceRefs`、`brief.isOpinion`；不得有 `articleHref`，不得生成详情页入口。
- `article` 必须有 title、summary、正文 sections 和显式 `article.sourceRefs`；详情页与集合预览只能使用同一 title。
- 两种形态均可保留完整 `EvidenceUnit → Source` 治理数据，但默认页面不投影治理标签。
- 当前 8 条 2026-07 事件按读者任务全部先归为 Brief；并非因为它们不重要，而是它们目前不承担独立论证责任。现有两篇旧文章不自动改写、迁移或删除；需内容负责人后续单独决定。

`/observations` 是独立集合页：使用唯一 `CollectionLayout`，最大 736px 且在 1280px shell 中居中；页标题、内容流和来源行共享同一 x 轴。不能把双栏主栏的左对齐当作集合页布局。

## 6. 组件、职责与迁移

| 责任 | 组件/层 | 规则 |
| --- | --- | --- |
| 全局身份 | `SiteHeader` + site identity 内容字段 | 横向 lockup；不写死作者文字 |
| 首页 | `HomePage` | 定位语 + 两项实践入口；不复用 Robotaxi 页面 |
| 作品母版 | `WorkFrame` / Practice / Framework 组合 | 第一段说明、第二段真实视觉；右 rail 可选 |
| 集合容器 | `CollectionLayout` | 仅拥有观察页居中宽度 |
| 简讯 | `BriefItem` | 四行固定语法，无卡片/详情 |
| 文章 | `ArticlePreview` / `ArticlePage` | 一标题、维度、摘要、正文、最终来源 |
| 内容查询 | repository/query | 根据 `presentation` 选择投影；Brief 与 Article 不互相自动推导 |

视觉值只在 tokens；LayoutShell、TwoColumnLayout、CollectionLayout 只拥有父级几何；组件只拥有内部组成；内容 JSON 不持有 CSS 或 JSX。

## 7. 验收合同

### 结构

- header 身份组为同一行、8px 左右间距、无分割符；1440 / 390 / 320 均不换行、不挤压导航或菜单。
- 首页定位语只出现一次；Robotaxi/企业页左栏均按“说明 → 视觉”两段，右栏只使用同一观察投影。
- 双栏间距精确来自 48px token；右栏 320px，不拉伸。移动单列不出现横向滚动。
- 观察集合页的流在 shell 中居中，而非左贴双栏主列。

### 内容语义

- 每条 Brief 必有 `日期/主体`、`#维度`、事实正文、末行来源链接；没有标题、摘要、CTA、articleHref 或治理标签。
- 每篇 Article 只有一个可追溯 title，且页面末行有来源链接；禁止在 reader UI 展示 claimKind、`事实/分析`、来源等级或“证据边界”等内部标签。
- Brief 与 Article 的投影必须来自显式 presentation 字段；不能用文字长度、level、来源数量或 `articleHref` 推断。

### 视觉与交互

- desktop 1440/1024，mobile 390/320：零横向溢出、中文业务词组不错误拆分、正文和来源的相邻间距一致。
- 简讯无阴影、无卡片 lift；文章链接、来源链接、节点、图框均具有可见键盘焦点和正确可访问名称。
- Framework 保留数据边集和几何回归检查；视觉改造不得改变权威概念、关系或 Robotaxi 事实边界。

### 工程与发布

- 本轮为一次产品版本迭代：变更 schema、查询、页面组件、token、测试和文档，并通过 `npm run release:check`。
- 后续只要 `presentation` 已存在：新增 Brief 或 Article 必须只修改单篇 `content/observations/*.json`，并走 candidate → draft → preview → human review → promote → `publish-content.command`；不再修改 UI 代码。
- 任何真实 Robotaxi 模块仅新增已验证媒体 manifest 与 Practice JSON；不允许用页面代码或占位图补足内容。

## 8. 不在本轮范围

- 不新增 Robotaxi 模块、截图或深链；它们等待真实证据。
- 不删除或重写两篇旧观察文章。
- 不制作企业框架未确认的局部视图。
- 不发布、不推送、不改 DNS；由 Engineering 在完成并获得本 task 专业验收后按用户授权执行。
