# v0.24.26 空内容安全与完整内容目标能力方案

## 根因

v0.24.25 产品 build 默认不消费独立内容，这是正确的边界；但页面解析器在内容为空时仍访问 `profile.id`，导致 `/about` 渲染崩溃。同时独立内容 CLI 只支持 `content/article/practice`，不能恢复 `profile` 与 `businessObservation`。

## 目标

产品无内容时所有公共路由仍可正常打开；独立内容 task 能完整管理现有内容对象，不把内容重新写入产品版本。

## 实施范围

- 所有 page content resolver 对缺失对象安全返回 `null`/空集合；`/about` 不得因 profile 缺失崩溃。
- 增加空内容路由回归测试：`/`、`/products`、`/business-observations`、`/observations`、`/about` 均保留网站名、主导航、页脚和合法空状态。
- 独立内容目标支持 `profile` 与 `businessObservation`，并保留 `content/article/practice`。
- 内容发布包为每个目标生成独立 `contentReleaseId/contentHash/baseSiteArtifactId/deployment/publicVerify`。
- 产品 build 继续默认不读取 `.content-workspace/content`；产品 manifest 不承载内容发布身份。

## 初始内容恢复范围

- `profile/about.json` → `/about`
- `products/robotaxi.json` 与 Robotaxi media manifest/MP4 → `/products`
- `articles/enterprise-operating-system.json` → `/business-observations`
- `business-observations/enterprise-operating-framework.json` → 首页业务观察对象
- `observations/*.json`：当前仓库实测 30 个，全部 `published`

## 非目标

不修改 UI、IA、schema、路由或上游事实；不回写 v0.24.25；不让内容 task 修改 `src/`、产品版本、commit/tag；不创建并行 task、branch、worktree 或 automation。

## 验收

- 空内容 build 后五个公共路由均无运行时错误，`/about` 不崩溃。
- 产品 dist 不含独立内容；产品 release/content manifest 无内容发布字段。
- profile、businessObservation、content、article、practice 均可独立 prepare/build/transport/finalize。
- 内容发布失败保留 draft/review/recovery/package，不污染产品版本。
- 初始内容恢复清单按仓库实测数量执行，发布证据逐项可追溯。
