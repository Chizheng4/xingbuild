# v0.9.0 全站内容卡片与页面结构收敛方案

## 1. 文档状态

- 版本：v0.9.0
- 状态：设计定稿，等待 Engineering 实施
- 日期：2026-07-27
- 产品与视觉责任：当前设计 task
- 工程责任：`engin网站迭代`
- 适用页面：首页、观察页、作品页、关于我，以及首页复用的观察和作品集合

本方案继承暖白、墨色、赭色和编辑型排版，修订 v0.6.0–v0.6.2 中已经被真实页面反馈证明不足的桌面 rail、特色对象和通用大间距投影。它不改变网站信息架构、品牌、内容事实源或 v0.8.0 企业认知架构页面。

## 2. 结论

本轮不是分别修改九个位置，也不是把所有页面区域画成盒子，而是建立两个全站能力：

1. **统一页面骨架**：栏目标题、说明和主要内容使用一条稳定主轴；rail 只用于真正需要辅助导航的长篇阅读页面。
2. **统一内容卡片系统**：首页、观察页和作品页的重复可点击内容，全部由共享卡片外壳和受控内容类型 schema 渲染。

根本结构：

```text
Page Frame
├─ Page Intro
│  ├─ Identity（仅在有独立语义时出现）
│  ├─ Title
│  └─ Summary
└─ Content Collection
   └─ Content Card × N
      ├─ Title
      ├─ Summary
      └─ Metadata
```

页面负责选择和编排对象；卡片负责统一表达对象。页面不得拥有卡片内部排版和交互。

## 3. 已确认问题与根因

### 3.1 多套桌面坐标系

生产页面 1229px 宽度实测：

- 作品：`WORKS` x=87，标题 x=279，首项作品 x=87；
- 观察：年份 x=55，重点观察 x=175；
- 关于我：目录 x=143，正文 x=351；
- 首页：主要内容 x=87。

读者每进入一个栏目都要重新寻找正文起点。手机端反而因为取消 rail 更直接。

### 3.2 通用 128px 间距

`.page-stack` 把 `--rhythm-section` 同时用于不同关系，桌面实测达到 128px：

- PageIntro → 第一项内容；
- 首页一个栏目 → 下一栏目；
- 关于我导语 → 正文；
- 观察导语 → 年份和内容。

Maggie Notes 的副标题结束到卡片集合约 66px。差异不只是数值，而是 Maggie 的空间由内容关系拥有，xingbuild 当前由通用父级统一放大。

### 3.3 内容对象语法不一致

同一类观察同时存在：

```text
重点观察：元数据 → 标题 → 摘要 → 继续阅读
归档观察：左侧元数据 → 中间标题 → 右侧箭头
```

作品列表又使用一串不同层级的关键词作为 Identity。页面因此表现为多个临时模板，而不是一个内容系统。

### 3.4 重复或无效信息

- `WORKS / OBSERVATIONS` 与中文栏目标题及导航重复；
- 只有一个年份时显示 `2026` rail，没有导航价值；
- “继续阅读”与标题链接、整体内容对象重复；
- About 常驻目录没有产生足够导航收益，却制造独立坐标和空白；
- 作品关键词串不能帮助读者识别对象类型或状态。

## 4. 从 Maggie 学习的机制

只继承以下机制：

- 一条稳定主轴；
- 同类内容重复同一骨架；
- 标题、说明、元数据形成稳定阅读顺序；
- 整个内容对象可点击；
- 类型、时间和数量只在帮助理解时出现；
- hover/focus 只反馈“可以进入”，不制造表演性效果。

不复制：

- Maggie 的品牌色、花园隐喻、图标和暗色外观；
- 英文内容密度和字号比例；
- 完全无边界的卡片外观；
- 相对时间文案。

## 5. 页面骨架

### 5.1 唯一主轴

首页、观察、作品、关于我默认共享 `--measure-content` 版心和同一左侧内容轴。

桌面规则：

- Page Intro、Section Intro、卡片集合、About 正文首字统一；
- 不再用 Page Intro 的 160px 左 rail；
- 不再用年份 rail；
- 不再用 About 目录 rail；
- 宽图和架构图可以突破阅读列，但其所属标题仍回到主轴。

手机规则：

- 沿用同一内容层级；
- 只缩小 gutter、字号、间距和网格列数；
- 不出现桌面独有的标签顺序或内容字段。

### 5.2 Page Intro

栏目页统一为：

```text
Title
Summary
```

Identity 仅在有独立语义时保留：

- 作品页：删除 `WORKS`；
- 观察页：删除 `OBSERVATIONS`；
- 关于我：保留 `金星 · XINGJIN`，置于标题正上方并共享主轴；
- 首页：保留作者 Identity，属于作者信息而不是栏目翻译。

目标节奏：

- Header → Page Intro 起点：桌面 48–56px，手机 32–40px；
- Identity → Title：8–12px；
- Title → Summary：20–24px；
- Page Intro → 第一内容集合：桌面 64–72px，手机 40–48px。

### 5.3 About

- 删除桌面常驻目录；
- About 正文回到统一主轴；
- 正文继续使用约 680–720px 阅读宽度；
- 保留语义标题层级，不把 About 章节卡片化；
- 如果未来内容显著增长，只允许在 Page Intro 下增加紧凑的行内页内导航，不恢复常驻 rail。

## 6. 共享卡片系统

### 6.1 卡片边界

卡片只对应一个真实、独立、可点击的内容对象。

使用卡片：

- 首页观察；
- 首页作品；
- 观察页文章；
- 作品页作品；
- 未来重复出现的工具、方法论和框架入口。

不使用卡片：

- Page Intro；
- 首页身份主张；
- 普通文章正文；
- About 普通章节；
- 只用于排版分组的 Section；
- 架构图中没有独立跳转或选择语义的装饰区块。

这修订 Visual System v1 的“不依赖装饰卡片”规则：**重复可点击内容对象允许使用有语义的卡片边界，任意页面区块仍不得卡片化。**

### 6.2 Card Base

所有内容卡片共享：

- 同一表面和边界 token；
- 同一 4px 以内克制圆角；
- 同一 padding 体系；
- 同一标题、摘要、元数据字体角色；
- 同一整体链接和点击区域；
- 同一 hover、focus-visible、active；
- 同一桌面和手机响应式规则；
- 同一内部关系 token。

推荐新增 token，不复用 `surface-subtle`：

```text
--color-card-surface: #F1EBE1
--color-card-surface-hover: #EDE5D9
--color-card-border: #D5CCBE
--radius-card: 4px
--shadow-card-hover: 0 8px 24px rgba(71, 52, 34, 0.06)
```

实际值可在当前暖色品牌范围内校准，但必须全站只有一组。

目标尺寸：

- 桌面 padding：28–32px；
- 平板 padding：24–28px；
- 手机 padding：20px；
- 卡片内部 `Title → Summary`：12–16px；
- `Summary → Metadata`：20–24px；
- 卡片集合 gap：桌面 24–32px，手机 16–20px。

静态状态安静，不使用常驻重阴影。

### 6.3 交互合同

卡片整体为唯一主链接：

- 整张卡片可点击；
- 标题不再创建第二个嵌套链接；
- 删除“继续阅读”“查看作品”等卡片级重复 CTA；
- hover：表面轻微加深、边界略增强、整体上移最多 2px；
- focus-visible：使用明确赭色轮廓，不能只依赖背景色；
- active：取消上移或下压 1px；
- 过渡 140–180ms；
- `prefers-reduced-motion` 下取消位移，只保留颜色和轮廓；
- 不使用缩放、发光、渐变动画和多层阴影。

栏目级“查看全部”可以保留，因为它进入集合，不与单张卡片动作重复。

## 7. 内容类型 schema

### 7.1 统一读取顺序

所有卡片使用：

```text
Title
Summary
Metadata
```

卡片视觉外壳完全一致。不同类型只允许必要字段不同，不得为了等形增加虚假字段。

### 7.2 ObservationCard

```text
title
summary
format
primaryTopic
publishedAt
href
```

显示顺序：

```text
文章标题
1–2 句摘要
内容类型 · 主题 · YYYY-MM-DD
```

规则：

- 首页和观察页使用同一个组件；
- 取消 `ObservationFeature` 与 `ObservationRow` 两套 DOM 和视觉语法；
- 不显示“继续阅读”；
- 不显示只有一个年份时的年份分组；
- 将来出现两个及以上年份且年份帮助浏览时，年份作为集合分组标题回到主轴，不恢复侧 rail；
- 同一集合内所有观察卡片字段顺序、padding、交互一致；
- 不通过第一项自动显示摘要、其他项隐藏摘要制造个性化。

### 7.3 WorkCard

```text
title
problemSummary
status
updatedAt
href
```

显示顺序：

```text
作品标题
作品面对的问题或一句构建说明
状态 · 更新于 YYYY-MM-DD
```

规则：

- 首页和作品页使用同一个组件；
- 删除列表中的 `经营模拟 · 业务架构 · B 端产品 · 工程实现` 等关键词串；
- 卡片不展示完整证据边界、详细构建说明或架构图；
- 详细证据、边界和架构进入作品详情页；
- 不显示无语义序号。

### 7.4 首页复用

首页不创建 `HomeObservationCard` 或 `HomeWorkCard`：

```text
Home
├─ Hero
├─ 最新观察
│  └─ ObservationCard × N
├─ 核心作品
│  └─ WorkCard × N
├─ About 摘要
└─ Site Status
```

首页只控制展示数量和栏目顺序，不改变卡片字段、样式或交互。

## 8. 集合布局

### 8.1 桌面

- 首页观察：2 列；
- 首页作品：2 列；
- 观察页：2 列；
- 作品页：2 列；
- 每个集合使用同一 Card Grid 原语；
- 同一行同类型卡片视觉等高，但不截断重要标题；
- 不设置“第一张特色卡片”专属构图。

### 8.2 平板与手机

- `< 900px`：单列卡片；
- 页面和卡片保持同一主轴；
- 不切换字段顺序；
- 不把 Metadata 移到标题上方；
- 不新增手机专属 CTA；
- 557px/520px 导航规则继续继承，不改变品牌色。

如果 Engineering 在真实宽度验证中证明 768px 两列仍可保持每张卡片至少约 320px 可读宽度，可以保留两列到内容驱动断点；不得只为了填满空间保持两列。

## 9. 空间系统修订

本轮取消“所有顶层兄弟统一使用 `--rhythm-section`”的直接投影。

关系合同：

| 关系 | 桌面 | 手机 |
| --- | ---: | ---: |
| Page Intro → 第一集合 | 64–72px | 40–48px |
| Section → Section | 72–88px | 48–64px |
| Section Intro → Card Grid | 32–40px | 24–32px |
| Card → Card | 24–32px | 16–20px |
| Card Title → Summary | 12–16px | 10–14px |
| Card Summary → Metadata | 20–24px | 16–20px |
| About 小标题 → 正文 | 16–24px | 14–20px |
| About 章节 → 章节 | 56–72px | 40–56px |

约束：

- 同一距离只由共同父级拥有；
- 不通过上下两个 margin 叠加；
- 不用空元素、空段落或 `<br>` 制造距离；
- 不为页面单独写 magic number；
- 128px 仍可用于真正的首屏或大叙事边界，但不得作为默认 PageStack gap。

## 10. 工程结构

推荐结构：

```text
content
├─ observations
└─ works

components
├─ cards
│  ├─ ContentCard
│  ├─ CardTitle
│  ├─ CardSummary
│  └─ CardMeta
├─ ObservationCard
├─ WorkCard
└─ CardGrid

pages
├─ HomePage（选择内容）
├─ ObservationsPage（选择观察集合）
├─ WorksPage（选择作品集合）
└─ AboutPage（非卡片正文）
```

这不是要求为每一行创建组件。Engineering 可以使用更小的实际结构，但必须满足：

- Card Base 单一事实源；
- ObservationCard 单一事实源；
- WorkCard 单一事实源；
- 首页只复用，不复制；
- 不允许页面 CSS 覆盖卡片内部；
- 内容字段、视觉 token、组件与页面责任分离。

## 11. 需要删除或替换的现有结构

- PageIntro 的桌面 rail 构图；
- Works / Observations 重复英文 eyebrow；
- `.year-group` 的年份 rail；
- 当前只有一个年份时的 `2026`；
- About 常驻 `.about-toc`；
- `ObservationFeature` 与 `ObservationRow` 的双实现；
- `.feature-link` 的“继续阅读”；
- 卡片内独立远端箭头；
- WorkSummary 的关键词 eyebrow；
- Work 列表中的详细 evidence 和 architecture 投影；
- 页面专属卡片选择器与交互覆盖；
- 默认 128px `.page-stack` 对所有关系的统一控制。

删除组件或字段前必须核对其他页面消费，不得只用 `display:none` 保留错误模型。

## 12. 不做范围

- 不修改导航、wordmark、页脚和品牌名称；
- 不修改 v0.8.0 企业认知架构的节点、关系、箭头和交互；
- 不重写观察文章和作品详情事实；
- 不修改 career、Robotaxi 上游事实；
- 不加入筛选、搜索、分页或新内容类型；
- 不加入深色模式；
- 不复制 Maggie 的品牌和图标；
- 不发布、不推送、不改 DNS。

## 13. 验收合同

### 13.1 结构

- 首页、观察页、作品页、About 的标题和主要内容共享同一左轴；
- About 不再有常驻目录 rail；
- 单一年份不显示年份分组；
- 首页观察与观察页使用同一个 ObservationCard；
- 首页作品与作品页使用同一个 WorkCard；
- 同类型卡片 DOM、字段顺序、交互完全一致；
- 页面只控制集合和布局，不控制卡片内部。

### 13.2 视觉

- 1440、1024、768、557、520、390、320px 真实浏览器检查；
- 没有 128px 通用间距造成的无意义空洞；
- 卡片在静态状态清晰但克制；
- hover 只有一组全站行为；
- focus-visible 明确；
- 同类卡片在同一行对齐；
- 中文标题不拆开 `企业数字化`、`Robotaxi` 等受保护词组；
- 无横向滚动。

### 13.3 内容与交互

- 没有“继续阅读”等重复动作；
- 没有作品关键词堆叠；
- 每张卡片整体可点击且只有一个主要链接；
- 键盘可以按阅读顺序访问所有卡片；
- 卡片 accessible name 能明确表达目标内容；
- reduced-motion 下没有位移动画；
- 栏目级“查看全部”仍可访问完整集合。

### 13.4 工程与回归

- 测试锁定同类型卡片共享 schema 和组件；
- 测试锁定首页不得复制卡片结构；
- 测试锁定 ObservationCard / WorkCard 字段顺序；
- 测试锁定不存在 `继续阅读`、单一年份 rail 和 About 常驻目录；
- v0.8.0 企业认知架构页面完整回归；
- 手机导航完整回归；
- console error/warning 为 0；
- `git diff --check` 通过；
- `npm run release:check` 通过。

## 14. Engineering 执行与回传

Engineering 先读取 AGENTS、迭代规则、本方案、Visual System v1 和当前实现，再形成文件级计划并直接实施。

实施完成后：

1. 不创建 commit/tag；
2. 不 push、不发布；
3. 主动回传当前设计 task；
4. 回传修改文件、组件/内容边界、响应式结果、自动检查和真实浏览器证据；
5. 由当前设计 task 做结构、视觉、卡片一致性、交互和响应式专业验收；
6. 只有验收通过后，Engineering 才创建本地 commit 和 `v0.9.0` tag。
