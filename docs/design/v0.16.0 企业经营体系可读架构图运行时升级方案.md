# 企业经营体系可读架构图运行时升级方案

状态：已批准的产品与视觉方案  
目标版本：`v0.16.0`  
授权边界：本文件是 Engineering 实现与专业验收合同；不授权扩大范围、提前发布或修改上游业务事实。

## 1. 结论

企业经营体系从“手工坐标绘制、受控平移的图形画布”升级为“分层阅读、自动布局、读者可聚焦的业务架构界面”：

> 企业经营体系总览 → 数字化实现局部平面 → 节点聚焦解释

主运行时采用 `@xyflow/react`（React Flow）的只读交互能力；`elkjs` 的 ELK Layered 负责确定性布局与正交关系路由。布局在构建阶段生成，读者端不执行异步自动排版，不出现首屏跳动，也不把 ELK 体积加入主要浏览器 bundle。

本轮不改变 `career` 同步快照、`frameworkModel` 的概念、定义、作用、节点、边或方向；不扩展第二个局部入口，不涉及 Robotaxi 公开内容、媒体与发布。

## 2. 为什么需要升级

当前 v0.15.0 已经验证了“总览 → 数字化实现”的真实阅读路径，但其图形仍主要由手工投影坐标、SVG path 和内部画布平移承担：

- 构图质量依赖逐视口手调坐标，新增合法视图时维护成本高；
- 手机需要在固定窗口内移动纵向世界，读者容易把精力花在寻找内容而不是理解关系；
- 节点、边、标签、键盘与视口行为由自建能力分别维护，难以持续获得成熟图形生态的改进；
- 当前只解决“可以下钻”，尚未形成稳定的“整体理解 → 局部理解 → 当前节点理解”三级阅读节奏。

根因不是视觉颜色不足，而是业务事实、布局计算和交互渲染仍耦合在自定义画布实现中。

## 3. 产品目标与非目标

### 3.1 目标

- 读者在首次进入时能看出企业经营体系的主要层次和反馈关系。
- 读者可以从唯一入口进入数字化实现，并理解 9 个节点、13 条边的完整结构。
- 选择节点后，读者立即看到该节点的权威定义、作用和直接关系。
- 桌面以架构图为视觉主角；手机以自然页面滚动顺序阅读，不使用巨大可拖拽画布。
- 上游模型变化后，可以通过同一布局流水线生成稳定投影，不再逐条手写 SVG path。

### 3.2 非目标

- 不提供图形编辑、拖动节点、连线、删除、多人协作或保存布局。
- 不增加缩略图、通用工具栏、缩放百分比、自由框选或 React Flow 默认产品化控件。
- 不把 Markdown、D2 或 Slidev 变成网站运行时或业务事实源。
- 不新增第二个局部入口、节点详情页或二次下钻。
- 不修改 Robotaxi 页面、媒体、内容对象、Observation 或全站导航。

## 4. 读者信息架构

### 4.1 第一层：体系总览

- 路径保持 `/business-observations`。
- 展示企业经营体系全局节点和真实关系。
- 默认聚焦 `enterprise-reality`，但所有节点保持同等业务真实性，不制造“主角节点”。
- `digital-implementation` 保留唯一可进入局部平面的明确提示。

### 4.2 第二层：数字化实现局部平面

- 路径保持 `?view=digital-implementation`。
- 完整投影现有 9 个节点、13 条边，默认聚焦 `b2b-product-architecture`。
- 返回总览、刷新恢复、安全未知参数回退继续沿用 v0.15.0 合同。
- 平面本身不继续下钻；节点选择只进入第三层阅读状态。

### 4.3 第三层：节点聚焦

- 节点聚焦是当前平面内的阅读状态，不新增 URL、页面或内容对象。
- 选中节点使用克制强调色；与其直接相连的节点和边保持正常对比，其余内容降低一级但仍可读。
- 权威解释固定按“定义 → 作用 → 直接关系”呈现，全部由当前 active architecture 计算。
- hover/focus 只做瞬时预览；click、Enter、Space 才改变持久选中。

## 5. 页面与响应式合同

### 5.1 桌面

- 保持 `ShowcaseLayout` 的 208px 说明列 + 20px 关系间距 + `SystemStage`。
- 左列展示当前节点权威解释，右侧架构图为视觉主角。
- 总览和局部平面首次进入均自动 `fitView`，不要求读者先缩放或拖动才能看见有效内容。
- 允许背景受控平移以查看关系细节；节点不可拖动、不可连接。
- 不显示 React Flow 默认 MiniMap、Controls、Attribution 以外的无关产品控件；保留网站自己的返回与复位控制。

### 5.2 520px 以上窄屏

- 继续使用单列页面，但保留桌面语义顺序：架构图 → 当前节点解释。
- 图形宽度适配容器，节点字号与点击区域不低于全站既有可读标准。
- 不因空间不足改变全局品牌色或节点字段顺序。

### 5.3 手机

- 使用 ELK 的独立 `DOWN` 纵向布局配置，但节点与边的业务身份、方向和标签与桌面一致。
- GraphCanvas 作为正常文档内容完整参与页面滚动，不建立需要上下拖拽的第二滚动世界。
- 单个平面高度由节点数量和布局结果决定，但设定产品预算；数字化实现目标高度为 620–760px，超出预算时构建检查失败，不通过缩小文字解决。
- 选中节点解释在图后 12–16px 紧接出现，并带“当前节点”状态标识；不同内容对象之间保持 40–48px。
- 点击图中节点后，若解释不在可视区域，使用 reduced-motion 兼容的受控滚动把解释标题带入视野。

## 6. 技术与责任分层

### 6.1 业务事实层

唯一事实源仍为 `src/content/frameworkModel.js`：

- 节点 id、名称、层级、定义、作用；
- 边 id、source、target、关系标签与方向；
- 总览和数字化实现的对象边界。

不得为了 ELK 排版方便合并节点、删除边、反转 source/target 或改写关系文案。

### 6.2 Presentation（展示配置）层

新增独立的架构图展示配置，只允许包含：

- desktop/mobile 的布局方向；
- 节点尺寸角色；
- layer、group、model order、port side 等布局约束；
- 节点与边的视觉类型；
- 视口 padding、最大宽高和 fitView 预算。

展示配置不是业务事实，不得保存定义、作用或关系文本副本。

### 6.3 Layout（布局生成）层

- 使用 `elkjs` 和 `org.eclipse.elk.layered`；运行时图形组件使用 `@xyflow/react`。
- 构建阶段分别为总览/数字化实现生成 desktop/mobile 布局。
- 使用固定算法配置、固定输入顺序与显式 port 约束，保证同一输入生成相同结果。
- 采用 orthogonal routing；反馈边可通过布局约束绕行，但最终箭头语义必须保持原始 source → target。
- 生成结果接受几何校验后才进入客户端产物；布局失败、节点重叠、标签裁切或预算超限均硬失败。

### 6.4 Runtime（读者运行时）层

- 使用 React Flow 渲染生成后的节点与边。
- `nodesDraggable=false`、`nodesConnectable=false`，不启用删除和编辑键盘语义。
- 只保留节点聚焦、背景平移、fit/reset、视图进入/返回和必要键盘操作。
- 使用中文 `ariaLabelConfig`，节点和边的可访问说明与网站真实操作一致。
- ELK 不进入主客户端执行路径；路由懒加载企业经营体系图形模块，避免影响其他页面首屏。

## 7. 视觉系统

- 继续使用全站暖白画布、墨色正文、暖赭强调色和既有字体角色。
- 节点表面只表达真实业务对象边界，不增加玻璃、渐变、发光、厚阴影或“科技蓝”。
- 边默认使用低对比墨灰；当前关系使用强调色，但不通过多种彩色线制造分类。
- 层级通过节点位置、字号、留白和关系方向表达；分组背景只在确有业务平面边界时使用。
- 关系标签必须靠近所属边段，不与节点、其他标签或箭头重叠。
- React Flow 的 DOM 结构不得带入与网站卡片系统冲突的默认视觉。

## 8. 状态与交互合同

必须覆盖：

- overview / digital-implementation；
- default / preview / selected；
- loading layout artifact / ready / hard failure；
- mouse / keyboard / touch；
- normal motion / reduced motion；
- direct URL / refresh / unknown view / browser Back / explicit return。

布局产物缺失或校验失败时，不渲染空白画布；页面显示同源节点与直接关系的受控文本降级，不伪造图形。

## 9. 性能与可用性预算

- 企业经营体系模块按路由懒加载；其他首页和页面不得引入 React Flow 运行时代码。
- ELK 只在构建阶段运行，不增加浏览器主线程布局等待。
- 图形首次可见时不发生从零坐标到最终坐标的跳动。
- 1440、1024、768、557、390、320 均无横向溢出。
- 手机不出现内外双重纵向滚动。
- 节点触控目标至少 44px；正文和关系标签不能依赖缩放才能阅读。

## 10. 自动验收

- `frameworkModel` 总览边集不变；数字化实现保持 9 节点、13 边。
- 业务事实与展示配置之间不存在名称、定义、作用或关系文案副本。
- 同一输入连续两次生成的布局 JSON 完全一致。
- desktop/mobile 均无节点碰撞、边穿越无关节点、端点悬空、标签裁切和预算超限。
- 所有生成边保持原始 source/target，不因 ELK cycle breaking 改变业务方向。
- React Flow 运行时不支持节点拖动、连线、删除或保存。
- URL、返回焦点、默认选中、聚焦关系、键盘、中文 aria-live 与 reduced-motion 合同通过。
- 非经营体系路由的构建产物不加载图形路由 chunk。

## 11. 真实页面验收

- 1440×900：总览全局关系可辨；进入局部、节点聚焦、说明同步、返回和复位均成立。
- 1024×768：双栏成立，图形不挤压说明，节点和标签可读。
- 768×1024、557×900：单列顺序明确，图与解释归属清晰。
- 390×844、320×568：纵向图随页面滚动，无嵌套纵向拖拽、横向溢出或文字缩小；选择节点后解释可到达。
- 键盘完成总览进入、节点选择、返回和复位；屏幕阅读器得到中文、非编辑型操作说明。
- console error/warning 为 0；路由切换不遗留 resize、pointer 或 layout worker。
- 公网验收覆盖 `/business-observations` 与 `?view=digital-implementation` 的关键状态。

## 12. 风险与控制

- **自动布局破坏业务语义**：业务 source/target 与展示约束分离，构建时做双向一致性校验。
- **React Flow 默认像编辑器**：关闭编辑能力和无关控件，用网站节点、边和 focus token 覆盖默认外观。
- **手机图过长**：采用独立纵向布局和高度预算；超限调整布局约束，不缩小文字或恢复内部滚动画布。
- **依赖体积扩大**：ELK 构建时使用，React Flow 仅路由懒加载，并记录升级前后 chunk 预算。
- **一次替换导致回退**：保留现有 `frameworkModel` 和文本降级；新运行时完成完整矩阵前不得删除旧图形实现。

## 13. Engineering 建议拆分

保持一个产品版本，但按以下内部顺序串行完成：

1. 建立展示配置、ELK 构建生成与确定性几何测试。
2. 建立只读 React Flow adapter、网站节点/边组件和可访问语义。
3. 迁移总览，保持现有 URL、默认选择和权威解释。
4. 迁移数字化实现局部与返回链路。
5. 收口手机自然滚动投影、性能预算和降级。
6. 完成自动测试、真实浏览器矩阵、版本收口与公网验收。

## 14. 交 Engineering 门槛

- v0.15.8 已完成归档、push、部署和公网验收。
- 本方案已固定目标版本、依赖选择、读者路径、响应式与验收合同。
- `docs/iterations/current.md` 必须只指向唯一 `v0.16.0`，Engineering 才能开始实现。
- Engineering 发现业务事实、核心路径、依赖可行性或验收合同冲突时必须回到产品确认；普通实现细节不回流产品 task。

## 15. 外部技术依据

- [React Flow 官方布局说明](https://reactflow.dev/learn/layouting/layouting)：React Flow 不内置自动布局，ELK 是支持动态节点尺寸、子流和边路由的完整布局选择。
- [React Flow 官方无障碍说明](https://reactflow.dev/learn/advanced-use/accessibility)：节点、边具备键盘与屏幕阅读支持，可通过 `ariaLabelConfig` 本地化读者指令。
- [ELK Layered 官方说明](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)：分层算法适合强调方向的架构关系，并支持正交路由、端口约束、边标签和跨层关系。
