# v0.24.25 产品与独立内容发布边界解耦方案

## 根因

v0.24.24 的产品构建与页面 repository 直接读取 `.content-workspace/content`，因此产品 dist 携带了 Robotaxi 正文与媒体。公网可见不代表内容独立发布成功，产品发布与内容发布的 source、manifest 和生命周期被重新耦合。

## 目标

产品发布只消费产品能力与稳定产品源；独立内容发布只消费独立内容包。两者可以分别构建、部署、验证和回滚，任何一方失败不污染另一方的版本事实。

```text
产品源/能力 → product dist → product transport
独立内容源 → contentReleaseId/hash → baseSiteArtifact → content transport
```

## 实施范围

- 产品 build 不读取或复制 `.content-workspace/content`、独立运营媒体和内容发布账本。
- 页面在无内容时保持合法空状态；内容渲染能力与内容对象数据分离。
- 产品 manifest 不写入 `contentReleaseId`、内容 hash、内容 deployment 或内容 publicVerify。
- 内容 prepare/build/transport/finalize 使用独立内容源、独立日志、ChangeSet/recovery 和明确 `contentReleaseId`。
- 内容包可选择一个 immutable `baseSiteArtifact` 作为构建输入，但不得从产品当前工作区隐式带入内容。

## 非目标

不修改 UI、IA、schema、路由、视觉系统或上游事实；不回写 v0.24.24；不创建并行 task、branch、worktree 或 automation。

## 验收

- 产品 dist 不含独立内容正文和运营媒体。
- 产品发布后公网不因产品构建自动出现未独立发布内容。
- 独立内容发布成功时具备 `contentReleaseId`、content hash、baseSiteArtifactId、deployment、publicVerify。
- 产品版本迭代期间内容仍可独立发布；内容失败保留 draft/review/recovery/package，不改变产品版本。
- 产品与内容各自的 transport 只验证自身身份和证据。
