# v0.15.0 企业经营体系总览与数字化实现局部视图方案

## 1. 结论

本轮只建立一条完整且可验证的认知下钻：

> 企业经营体系总览 → 数字化实现局部视图 → 返回总览

首版唯一入口是总览节点 `digital-implementation`。局部视图直接消费
`frameworkModel.architectureById.get("digital-implementation")`，不得复制、改写或缩短其中的节点、定义、作用、边和关系标签。

这是一个产品能力版本，不是新增第二张公开长页面，也不是继续扩展企业现实、企业业务架构或 Robotaxi 应用。

## 2. 页面与对象责任

### 2.1 页面

- 路径保持 `/business-observations`。
- 无 `view` 参数时显示企业经营体系总览。
- `?view=digital-implementation` 时在同一展示母版、同一画布位置显示数字化实现局部视图。
- 未知 `view` 值回退总览，不渲染空白或错误局部图。
- 首版不增加 `node` URL 参数。

### 2.2 单一事实模型

- 总览事实源：`architectures[id="enterprise-operation"]`。
- 局部事实源：`architectures[id="digital-implementation"]`。
- 局部固定为 9 个节点、13 条边，默认节点为 `b2b-product-architecture`。
- 当前节点的定义、作用、直接关系必须从当前 active architecture 计算；不得继续从总览边集读取局部关系。
- `activeViewId` 只选择模型投影，不改变任何概念事实。

### 2.3 状态

- `activeViewId`：`overview | digital-implementation`。
- `selectedNodeId`：当前事实模型内的持久选择。
- `previewNodeId`：hover/focus 的瞬时预览。
- `viewportTransform`：当前视图自己的平移状态。
- 切换视图时清空 preview、重置 viewport，并使用目标视图默认节点。

## 3. 交互合同

### 3.1 进入

- 总览中的 `digital-implementation` 是唯一具有下钻能力的节点。
- 鼠标点击、Enter 或 Space 直接进入局部视图，并把 URL push 为
  `?view=digital-implementation`。
- 该节点必须有克制但可识别的进入提示；不使用大 CTA、弹窗、双击或“先选中再点击一次”的隐藏规则。
- 其他总览节点仍只执行当前的选择与解释，不出现无效进入提示。

### 3.2 局部阅读

- 局部节点只支持 hover/focus 预览、click/Enter/Space 选中解释，不继续二次下钻。
- 默认选中 `B 端产品架构`。
- 左说明列继续显示当前节点名称、权威定义、权威作用和从局部边集计算的直接关系。
- 画布标题为“数字化实现”，不再重复“企业经营体系总览”。
- `复位视图`只重置局部平移和局部默认节点，不退出局部。

### 3.3 返回

- 局部画布工具区提供唯一“返回总览”控制。
- 返回时移除 `view` 参数，使用 replace 语义，避免浏览器后退立即重新打开刚退出的局部视图。
- 返回总览后选中并聚焦 `digital-implementation`，明确读者从哪里返回。
- 浏览器 Back 在刚进入局部后可自然回到总览。
- 直接打开或刷新局部 URL 后仍进入局部；刷新无参数 URL 时仍回到总览默认节点 `enterprise-reality`。

## 4. 构图与视觉

### 4.1 共用展示母版

- 不新增页面容器、卡片、弹层或图下 ExplanationPanel。
- 继续使用 `ShowcaseLayout`：左侧 208px 权威说明，20px 关系间距，右侧 SystemStage 为视觉主角。
- 总览与局部使用同一套暖白、墨色、赭色、节点、边、标签、选中和 focus token。
- 视图切换只允许 120–160ms 的轻透明度反馈；`prefers-reduced-motion` 下取消。

### 4.2 桌面

- 画布继续完整使用 SystemStage 的 16:10 区域。
- 使用 `digital-implementation.projection.desktop`、desktop viewBox 和 desktop edge paths。
- 上游输入锚点在上；产品与数据并行；技术架构、工程实现、数字化系统形成中轴；企业运作、事实结果、经营决策形成底部反馈；反馈轨位于节点外侧。
- 不能为了构图合并产品与数据、把系统等同企业现实，或删除事实→决策→业务架构反馈。

### 4.3 手机

- 总览保持现有可读投影。
- 局部视图使用模型已有的 mobile 节点、边、标签和 350×1010 世界坐标，不把桌面图等比缩小。
- 在小于 520px 时，局部画布采用紧凑固定可视区：常规手机约 335×520px，320px 视口约 288×460px；内部纵向图可受控上下平移。
- 初始视窗必须完整看见企业业务架构、B 端产品架构和数据架构；读者可向下平移查看实现链和反馈。
- 平移边界以“内部世界尺寸 - 可视区尺寸”计算，不能沿用总览的 ±8% 小范围 clamp，也不能把画布拖到纯空白。
- 图后 14px 内紧接当前节点说明；不得让说明看起来属于下一模块。
- 返回总览、复位视图均保留至少 44px 触控区域。

## 5. 图形工程与几何阻断项

- 桌面和手机必须使用同一节点、边和方向，仅坐标投影不同。
- 轨道本身没有箭头；只有进入真实目标节点的边有箭头。
- 每条关系文字只对应一条明确线段。
- 节点不得重叠；标签不得压线、压节点或被裁切。
- 边必须进入目标节点真实边界，不能悬空、落进节点内部或穿过无关节点。
- `di-product-data` 与 `di-data-product` 必须保持双向且线路可区分。
- `di-system-facts` 必须表达系统“记录”事实，不能覆盖企业运作“产生”事实。
- `di-decision-business` 必须经过事实与经营结果 → 经营分析与决策后返回企业业务架构。
- 几何校验必须对 `enterprise-operation` 和 `digital-implementation` 的 desktop/mobile projection 分别执行。

## 6. 无障碍与降级

- 所有节点继续是原生 button，保持 `aria-pressed`、focus-visible 和 aria-live 选中反馈。
- 可下钻节点的可访问名称必须说明“进入数字化实现”，普通节点仍说明“查看解释”。
- 返回和复位是两个语义不同的原生 button。
- 无 JavaScript 降级继续保留企业经营体系总览，不要求输出局部交互图。

## 7. 验收矩阵

### 自动合同

- model 保持总览固定边集，以及数字化实现 9 节点、13 边。
- URL view 解析、未知值回退、进入 push、退出 replace、刷新恢复。
- 总览和局部各自的默认节点、reset、返回锚点。
- 当前 active architecture 驱动 connected edges 和 direct relations。
- desktop/mobile 几何检查无节点碰撞、错误端点、穿越和裁切。
- reduced-motion、键盘、aria-live 合同。

### 真实浏览器

- 1440、1024：总览进入局部、九节点与十三边、左解释同步、返回锚点、平移和复位。
- 768、557：单列结构、桌面投影仍完整可读、图与解释归属明确。
- 390、320：纵向 mobile 世界在固定视窗内平移；默认区域可见；可到达底部反馈；不能拖出纯空白；解释紧随图；无横向溢出。
- 直接打开局部 URL、刷新局部 URL、未知 view、浏览器 Back、显式返回。
- console error/warning 为 0。
- 发布后在 `https://xingbuild.top/business-observations?view=digital-implementation` 复验同一矩阵的关键状态。

## 8. 明确不做

- 不增加第二个局部入口。
- 不展开企业现实、经营与架构设计、企业业务架构九视角、业务对象、底层概念语法或 Robotaxi 应用。
- 不增加节点详情页、node query、缩略图导航、缩放控件或小地图。
- 不改 frameworkModel 的概念、copy、节点或固定边。
- 不修改观察 Brief、Robotaxi 产品、About、全站导航或其他视觉系统。
