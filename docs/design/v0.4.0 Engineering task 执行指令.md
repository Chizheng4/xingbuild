# v0.4.0 Engineering task 执行指令

## 任务目标

在不改变 xingbuild 品牌、信息架构和内容事实的前提下，实施 Visual System v1，把 `v0.3.1` 的阅读路径升级为具有语义 token、稳定字体角色、流体空间、内容驱动响应式规则和清楚组件责任的 `v0.4.0`。

## 必读事实源

1. `AGENTS.md`
2. `docs/rules/iteration-and-release.md`
3. `docs/design/xingbuild Visual System v1.md`
4. `docs/design/v0.4.0 视觉系统工程化升级方案.md`
5. `docs/design/阅读路径与响应式布局升级方案 v0.3.0.md`
6. `docs/design/视觉系统与交互原则.md`
7. `docs/iterations/current.md`

## 执行边界

- 先检查 `v0.3.1` 之后的工作区和真实代码差异。
- 先在 Engineering task 中输出差异和文件级计划，然后直接执行；只有事实冲突、破坏性操作或必须扩大范围时才暂停。
- 不改 `siteContent.js` 中的职业、作品、Robotaxi 状态和证据事实，除非只是适配已有字段的展示。
- 不增加一级栏目、深色模式、CMS、搜索、筛选、Build Log 或自动分发。
- 不复制 Maggie Appleton 的字体和视觉资产。
- 不推送 GitHub、不发布 EdgeOne、不修改域名。

## 实施顺序

1. 建立 Visual System v1 token。
2. 收敛基础排版、版心和空间规则。
3. 分离已稳定的页面和组件责任。
4. 按首页、观察、正文、作品、关于我顺序适配。
5. 补充视觉系统合同测试。
6. 运行自动检查并修正结构错误。
7. 使用真实浏览器完成五个视口和核心状态验证。
8. 完成设计 QA。
9. 运行 `npm run release:check`。
10. 稳定后创建本地提交和 `v0.4.0` 标签。

## 强制验证

视口：

- 1440×1000；
- 1024×768；
- 768×1024；
- 390×844；
- 320×568。

路径：

- 首页；
- 观察列表；
- 短观察；
- 分析长文；
- 作品列表；
- 作品详情；
- 关于我；
- 手机菜单打开状态；
- 手机目录打开状态。

检查：

- 字体实际加载与回退；
- 中文标题换行；
- 正文行宽、字号和行高；
- 小字下限和对比度；
- 键盘焦点；
- 触控目标；
- 横向溢出；
- 架构图手机可读性；
- 无装饰性边框与卡片回潮；
- 无自动暗色切换；
- 浏览器控制台无错误。

完成后分别报告：

