# v0.8.0 单页交互式企业认知架构视觉提案

## 1. 状态

- 日期：2026-07-27
- 状态：单一推荐方向已形成，等待用户确认效果图
- 产品方案：`docs/design/v0.8.0 单页交互式企业认知架构方案.md`
- 视觉基线：`docs/design/xingbuild Visual System v1.md`
- 工程状态：未授权

本提案替代 v0.7.0 的浏览器式构图，但不修改上游权威概念。用户确认效果图之前，不移交 Engineering。

## 2. 推荐方向：编辑型系统图谱

整页像一篇可连续阅读的架构文章，而不是知识浏览器或 SaaS 控制台：

- 每张图由一个真实问题统领；
- 架构图是该段的主要阅读对象；
- 节点解释是当前选择的稳定补充；
- 暖白、墨色、赭色保持 xingbuild 品牌；
- 节点和线条精确，但不扩散为全站卡片化；
- 四张图从上到下连续出现，不提供视图切换。

外部机制只借鉴：

- IBM Technical Diagrams：稳定网格、正交关系、短标签、节点文字外置长解释、颜色不能单独承载语义；
- React Flow：节点、边和选中状态分离，选中后只更新直接关系；
- W3C：hover 信息必须可由 focus 获得，重要内容不依赖 hover；
- Observable：同一数据关系在不同容器宽度中重新布局，不把桌面图等比缩小。

## 3. 页面构图

### 3.1 桌面

- 最大版心 1312px，页面 gutter 40–64px；
- 标题区后直接进入架构一；
- 单个架构段顶部是 180px 栏目语义 + 问题和一句说明；
- 图与解释区约 64/36，间隔 48px；
- 每张图作为独立内容段，段间使用 92–104px 空间和一条低对比真实边界；
- 解释区在当前段内 sticky，不形成全页固定侧栏。

### 3.2 手机

- 20px 页面 gutter；
- 问题、说明、纵向完整架构、当前解释依次排列；
- 图节点最小 52px 高，点击目标至少 44px；
- 关系标签位于节点之间，不做横向图缩放；
- 解释区在当前图后方，不跳转、不折叠；
- 四张图全部保留在文档流。

## 4. 四张图构图

### 4.1 企业如何经营：反馈闭环

- 桌面使用上下两行闭环：外部环境与需求 → 企业经营体系 → 经营与架构设计；数字化实现 → 企业运作 → 事实与经营结果；反馈回到设计。
- 手机改为一条纵向因果链，最后用“运行反馈再次指导”明确返回关系。
- 默认选中“企业经营体系”。

### 4.2 业务如何被设计：价值形成与执行

- 第一行表达需求/事件 → 价值流 → 企业能力与资源；
- 第二行表达责任、流程、业务对象与事件；
- 第三行表达规则、事实结果、指标与目标差距；
- 关系不是九宫格分类，而是触发、需要、承担、执行、约束、改变、产生和衡量的组合。
- 默认选中“业务对象与事件”，因为它最能连接流程、规则、事实和数字化。

### 4.3 数字化如何进入企业运作：双轨汇合链路

- 企业业务架构提出数字化需求；
- B 端产品架构与数据架构并行；
- 二者共同进入技术架构与工程实现；
- 形成企业数字化系统，进入企业运作并记录事实结果。
- 默认选中“企业业务架构”。

### 4.4 复杂概念如何明确：五组底层语法

- 五个阅读组横向排列：现实参与、现实结构、现实变化、现实约束、证据与判断；
- 组内显示十类底层概念；
- 组间关系是参与、描述、改变、约束、记录与判断；
- 手机改为五组纵向排列，不做词典式两列网格。
- 默认选中“关系”。

## 5. 交互状态

### 5.1 节点

| 状态 | 视觉 |
| --- | --- |
| 默认 | 暖白底、1px 中性边界、墨色文字 |
| hover | 上浮 3px、赭色边界、直接关系线增强；不显示解释 tooltip |
| focus | 与 hover 同等反馈，额外 2px 外置焦点轮廓 |
| selected | 2px 赭色边界、轻暖赭底、明确“当前”文字标记 |

### 5.2 连接线

| 状态 | 视觉 |
| --- | --- |
| 默认 | 1px 中性线、关系标签使用 muted |
| 相关 | 1.5px 深墨线，直接相邻节点边界略加强 |
| 当前 | 2px 赭色线，关系标签使用深赭；仍保留箭头或线型语义 |

## 6. 尚未证实

- 1440px 首屏能否在真实站点页头与字体加载后完整看见第一张图主体，需要 Engineering 实现后再验证；
- 中文网页字体回退会影响节点高度，需要真实浏览器检查 320px 和 390px；
- 复杂连接线在 HTML + SVG 实现中的精确避让尚未验证，但当前节点规模不构成引入 React Flow、D3 或 Canvas 的证据；
- 本提案是视觉和交互依据，不代表正式工程已经实现。
