# v0.5.1 中文语义换行与公网验收修订方案

## 1. 结论

`v0.5.0` 的根本视觉构图已经成立，不需要再次模仿 Maggie Appleton 重做首页。下一轮应是最小稳定修订：

1. 修复核心中文标题把完整词组拆开的排版缺陷；
2. 校准相邻段落和内容对象之间的垂直节奏；
3. 将中文语义换行与相邻内容节奏写入 Visual System；
4. 补齐发布后版本、迭代和公网验收状态。

本轮不是调整几个孤立标题，也不是扩大为新一轮视觉风格设计。

## 2. 公网验收事实

验收日期：2026-07-25  
验收对象：`https://xingbuild.top`  
对照对象：`https://maggieappleton.com/`  
视口：桌面 1440×1000、手机 390×844，并对关键栏目做桌面与手机回归。

### 2.1 已通过

- 桌面首页主标题顶部约 204px、有效宽度约 940px，最新观察进入首屏；
- 手机首页主标题约 38px，第一篇重点观察标题进入 390×844 首屏；
- 衬线承担作者判断和阅读主体，无衬线承担解释、目录、状态和操作；
- 文章正文约 720px，桌面正文约 18px，手机正文约 16.5px；
- 桌面目录链接实际为无衬线、约 13px，不存在字体角色回退；
- `观察 / 作品 / 关于我` 桌面和手机均无横向溢出；
- 390px 菜单可展开为覆盖层，按钮切换为关闭状态，背景滚动锁定；
- 首页和文章页桌面、手机控制台均无 error 或 warning。

### 2.2 缺陷

桌面首页出现：

```text
把判断构
建成可以运行和验证的系统。
```

手机文章标题出现：

```text
需要同
时看见四个平面
```

`构建` 和 `同时` 都被拆开。它们会直接打断中文阅读，是当前最明显、也最值得修复的视觉缺陷。

### 2.3 尚未形成独立证据

当前 Chrome 环境直接访问线上 `release.json` 被客户端拦截，因此本次不把清单读取当作版本确认依据。用户已确认完成发布；公网页面的结构和实测数据与本地 `v0.5.0` 一致，但 Engineering 仍需通过既有发布脚本或可访问的版本清单补齐精确版本证据。

## 3. 与 Maggie 的本质对照

### 3.1 已接近的部分

- 都用强标题建立作者长期主题；
- 标题、解释、元数据和正文有清楚的字体角色；
- 桌面有编辑型留白，手机重新组织密度而不是更换品牌；
- 长文使用受控行宽和稳定行高；
- 首页能够自然进入真实内容，而不是停留在自我介绍。

### 3.2 不应继续复制的部分

- xingbuild 不需要插画、花园隐喻、成长阶段标签或 Canela；
- Maggie 的横线、提示框和英文超大字号不能成为 xingbuild 的通用脚手架；
- xingbuild 的观察与作品密度高于 Maggie 是内容模型差异，不是视觉落后；
- 当前暖白、墨色、赭色和克制的业务编辑方向应保持。

### 3.3 当前差距的本质

差距已经不再是“大布局不够像 Maggie”，而是中文排版精度：

```text
容器宽度正确
＋ 目标行数正确
≠ 中文阅读正确

中文阅读正确
= 视觉尺度
＋ 完整词组
＋ 跨视口稳定性
```

## 4. 上次方案的遗漏

`v0.5.0` 方案写了“自然中文换行”和目标行数，但没有定义：

- 什么叫自然；
- 哪些词组不得拆开；
- 使用什么 CSS 能力；
- 不支持该能力时如何回退；
- 验收是看行数，还是看实际断点。

因此这不是单纯的 Engineering 局部失误。设计合同不充分，使实现即使满足宽度、字号和两行目标，仍可能通过错误验收。本轮已在 Visual System v1 补齐该规则。

## 5. 工程方案

### 5.1 正确责任

- 语言上下文：文档与内容层；
- 换行策略：全局排版 foundation 或语义标题样式；
- 标题角色：现有 Hero、页面标题、文章标题、重点标题组件；
- 验收：视觉合同测试与真实 Chrome 多宽度检查。

不得在单篇文章或首页 JSX 中分别修补。

### 5.2 推荐实现

对 display、页面标题和文章标题建立统一语义规则：

```css
word-break: auto-phrase;
text-wrap: balance;
```

对重点观察和章节标题根据实测采用：

```css
word-break: auto-phrase;
text-wrap: pretty;
```

同时确认正确的 `lang="zh-CN"`。浏览器不支持 `auto-phrase` 时允许回退为普通中文断行，不增加 JavaScript 排版依赖。

### 5.3 禁止路径

- 为首页插入固定 `<br>`；
- 对 1440px 和 390px分别维护标题文案；
- 用不透明的 `max-width` magic number 推动某个字换行；
- 为两个缺陷建立专用组件；
- 引入第三方分词或排版依赖；
- 顺便调整颜色、Hero 高度、字体、导航或内容结构。

### 5.4 相邻段落与内容对象间距

Engineering 需要审计核心阅读页和首页内容流中“上一项 → 下一项”的实际距离，重点检查：

- 正文段落 → 正文段落；
- 标题 → 第一段；
- 正文 → 列表、引用和讨论问题；
- 一个论述的末段 → 下一个标题；
- 元数据 → 内容标题；
- SectionIntro → 第一项内容。

修订应复用 Visual System v1 的相邻内容节奏合同。优先由统一 flow 或相邻语义选择器实现，消除双边 margin 叠加、意外 margin collapse 和组件各自创造间距的问题。不得把所有段落统一成同一个距离，也不得借机压缩或拉大全站空间。

## 6. 验收标准

### 6.1 视觉

- 首页核心陈述在 1440、1024、768、557、520、390、320px 不拆开 `构建`；
- 文章标题在上述宽度不拆开 `同时` 和 `企业数字化`；
- 修复后不产生孤立标点、单字悬挂或新的异常三行标题；
- 正文连续段落、标题到正文、论述到下一个标题的间距符合各自语义关系；
- 相邻元素不存在双重 margin 造成的异常大空白，也不依赖 margin collapse；
- 手机端相邻节奏可更紧凑，但对象内部与对象之间的层级不能反转；
- v0.5.0 已通过的 Hero 起点、内容进入节奏、字体角色和阅读宽度不回退；
- 所有关键页面无横向溢出。

### 6.2 交互与工程

- 390px 全屏菜单和 557px 行内导航不回退；
- 首页、观察、文章、作品、关于我无控制台 error/warning；
- 视觉合同测试覆盖中文标题的计算样式或规则存在性；
- `npm run release:check` 通过。

### 6.3 版本状态

- 更新 `VERSION.md`，区分 `v0.5.0` 用户已发布、公网页面已验收与线上版本清单未由本次 Chrome 独立读取；
- 完成后将本轮移入 `docs/iterations/history/v0.5.1.md`；
- 创建本地提交与 `v0.5.1` 标签；
- 不自动发布，除非用户在 Engineering task 明确授权。
