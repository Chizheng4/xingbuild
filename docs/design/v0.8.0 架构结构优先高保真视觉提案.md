## 推荐方向

采用“容器化主脊柱 + 侧向作用 + 可闭合反馈轨道”，并继承 xingbuild 暖白、墨色、赭色和编辑型排版。

视觉优先级为：

1. 先看见系统边界和主关系；

3. 最后通过节点选中阅读解释；
4. 赭色只用于当前节点和反馈轨道，不承担唯一语义。

## 四张架构的构图定稿

### 企业经营体系

- 使用“系统容器 + 内部设计/现实/运作 + 外部事实反馈”；
- 外部环境位于系统边界外；
- 数字化实现是设计到企业现实的支路；
- 外部环境分别影响设计、构成企业现实条件；
- 经营分析与决策沿独立回程轨道调整选择与设计、影响后续运作，不直接跳级改变现实。

### 企业业务架构

- 使用纵向价值形成与执行主脊柱；
- 企业职能/组织停靠在能力侧面，表达责任承接；
- 业务规则停靠在流程和对象变化侧面，表达约束；
- 事实与结果向指标提供计算依据，指标衡量并比较目标差距；
- 差距通过外侧反馈轨道分别落到能力与资源、流程、规则，避免一线多义。

### 数字化实现

- 产品架构和数据架构在同一设计层并行且相互约束；
- 两条设计轨道汇入技术架构；
- 技术架构、工程实现、数字化系统分别表达设计、活动和结果；
- 数字化系统进入并支持企业现实中的企业运作；
- 企业运作产生事实，数字化系统记录事实，两条关系分别表达；
- 事实先支持经营分析与决策，再由决策调整企业业务架构。

### 底层概念语法

- `状态`与`关系`保持为两个独立概念；
- 主体参与活动，活动作用于对象；
- 主体和对象建立关系，主体、对象、关系分别具有状态；
- 事件分别改变状态和关系；
- 规则约束活动，并约束引起状态/关系变化的事件；
- 事实记录或验证状态、活动、事件；
- 指标基于事实计算，并衡量状态、过程和结果。
- 明确删除错误的“结果 → 事实”关系。

## 桌面与手机投影

### 桌面

- 页面维持编辑型阅读宽度；
- 架构图与解释区采用左图右解释；
- 主脊柱拥有最大的连续阅读空间；
- 侧向关系停靠在被作用节点附近；
- 反馈轨道沿图外缘返回，避免穿过主链。

### 手机

- 四张图仍在同一页面全部展开；
- 主脊柱改为纵向；
- 并行设计轨道保持并列后汇合，不改成先后步骤；
- 侧向约束通过缩进停靠和虚线表达；
- 反馈使用独立外侧回程轨道；
- 选中解释位于当前图下方，不遮挡架构。

## 互动状态

- 默认：完整显示核心节点、关系标签和反馈；
- hover/focus：仅提示节点可点击，并突出直接连接；
- selected：赭色边界稳定标识当前节点，桌面右侧或手机图下方显示解释；
- 选中时整图仍可见，不把架构退化为局部详情页；
- 颜色、线型、位置与动词标签共同表达关系，任一单独要素都不是唯一依据。
