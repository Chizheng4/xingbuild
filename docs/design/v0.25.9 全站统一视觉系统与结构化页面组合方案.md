## 1. 一句话结论

这是一次以现有页面架构为基线的全站视觉底层和页面组合能力升级，不是 `/products` 局部换皮，也不是重造网站：

1. 全站从当前暖白、编辑式视觉迁移为冷白、克制、专业、轻浮起的产品界面风格。
2. /products 仍是导航中的 B端产品 页面，但页面展示对象明确只有 Robotaxi 运营平台；它不是主页，也不是泛化的“B端产品”作品集合。
3. 页面内容保持当前内容对象和已确认顺序；后续由内容及发布 task 通过结构化字段和独立内容发布身份更新。
4. `/products` 始终按“说明 + 独立媒体槽位”成对渲染。Robotaxi 当前保留 4 个稳定模块；每个模块独立拥有可选 `mediaId`，未来对应 4 个不同媒体。当前上线初始内容允许 4 个模块分别引用同一个已批准视频，后续逐项替换互不影响。
5. 所有模块和媒体入口如果语义为进入产品，统一指向 Robotaxi 运营平台，用户可见标签为“进入 Robotaxi 运营平台”；“浏览经营观察”是单独的经营观察入口，不指向 Robotaxi。
6. 当前 4 个模块全部阅读结束后，才出现页面底部行动区（内部槽位名 `ClosingAction`）。它是第二次产品入口，不是重复模块、弹窗或关闭控件。
7. 全站首先统一 `VisualSystem → shared primitives → PageComposition`；首页、B端产品、经营观察、About 只组合共享能力，不拥有页面私有字体、间距、按钮、媒体或版心。

“使用当前网站内容”指：Engineering 读取当时已批准的内容对象做实现和测试；不复制静态正文。四个模块重复引用当前视频属于明确的初始内容配置，不是代码层自动继承，也不得宣称为四份不同证据。

## 3. 最小系统视图

本视图只表达责任和投影关系，不把页面导航、内容事实和工程组件混成一个业务模型。

~~~mermaid
flowchart TD
    A["现有产品总案\nIA / 对象 / 页面责任"] --> D["统一 VisualSystem\ntoken / grid / typography / state"]
    B["已确认 Web 视觉稿\nxAI 层级 + OpenWorker 浮起质感"] --> D
    C["现有 PageDefinition / RichDocument / SystemStage"] --> D
    D --> E["共享页面组件\nHeader / Hero / Showcase / Media / Reading / Footer"]
    E --> F["HomeComposition"]
    E --> G["ShowcaseComposition"]
    E --> H["ReadingComposition"]
    E --> I["CollectionComposition"]
    J["结构化内容对象 + 已批准媒体"] --> F
    J --> G
    J --> H
    J --> I
~~~

这张图的方向是：

- VisualSystem 是全站底层；它统一字体、颜色、网格、间距、媒体比例、浮起层级、按钮和所有状态；
- PageDefinition 拥有路由、页面组合、区域和语义约束；
- 内容对象拥有公开文本、模块顺序、批准媒体引用和可编辑行动文案；
- VisualGrammar 拥有颜色、字体、布局、状态和响应式投影；
- 内容 task 只能经由登记字段更新内容对象；
- 页面渲染不从聊天历史、DOM 文案或临时视觉稿推断业务事实。

## 4. 页面语义合同

### 4.1 /products 的身份

| 层 | 固定含义 |
| --- | --- |
| 菜单标签 | B端产品 |
| 页面路由 | /products |
| 页面组合 | ShowcaseComposition |
| 当前展示对象 | Robotaxi 运营平台 |
| 页面标题 | Robotaxi运营平台（使用当前内容源原值） |
| 页面任务 | 说明 Robotaxi 运营平台的经营结构，并展示其已批准的运行媒体 |
| 不得推导 | 不把页面称为主页、B端产品集合、经营观察首页或真实城市运营结果 |

菜单标签与内容标题不能互换：

- “B端产品”回答“用户正在访问哪一类产品菜单”；
- “Robotaxi 运营平台”回答“该页面正在展示哪个具体产品对象”。

### 4.2 动作语义

| 位置 | 用户可见文案 | 目标 | 是否可由日常内容 task 改写 |
| --- | --- | --- | --- |
| Hero 主动作 | 进入 Robotaxi 运营平台 | https://robotaxi.xingbuild.top/ | 否；语义和安全目标由产品合同锁定 |
| Hero 次动作 | 浏览经营观察 | 现有经营观察安全路由，默认 /business-observations | 文案可登记但不得改成 Robotaxi 入口；路由由产品合同锁定 |
| 模块媒体/模块入口 | 进入 Robotaxi 运营平台 | https://robotaxi.xingbuild.top/ | 否；不得显示含义不清的“查看作品” |
| 页面底部行动区 | 初始复用当前 Robotaxi 标题和边界 | 仍指向 Robotaxi 运营平台，除非另立产品方案 | 标题、说明、按钮文案可由内容 task 更新；目标类型不变 |
| 最新更新卡 | 最新更新 + Robotaxi 真实产品版本 | https://robotaxi.xingbuild.top/ | 否；版本读取 Robotaxi 已验证 release 事实，内容 task 不维护 |

SystemStage 的可访问名称、媒体 anchor 的 aria-label 和可见按钮文本必须同义。不能按钮写“进入 Robotaxi 运营平台”，无障碍名称却写“查看产品演示”。

### 4.3 内容流

/products 的公开内容顺序固定为：

~~~text
SiteHeader
→ LatestUpdateCard
→ ProductHero
→ ShowcaseModule × 4
→ 页面底部行动区（ClosingAction）
→ SiteFooter
~~~

- LatestUpdateCard 不能删除；它是页面的顶部版本/更新上下文，不改变页面对象身份。
- ProductHero 只出现一个页面级 H1。
- 每个 ShowcaseModule 是一个不可拆散的“说明 + 对应媒体”对象。
- 页面底部行动区（ClosingAction）必须位于所有模块之后，不能在第一个模块后插入。
- footer 处于自然文档流末端，不漂浮在模块中间。

## 6. VisualGrammar：全站冷白、高级、专业、克制

### 6.1 视觉原则

1. 冷白画布、清晰信息层级、少量蓝色动作强调。
2. 高级感来自留白、比例、文字层级和媒体质量，不来自装饰线、炫光、厚重 3D 或黑色大按钮。
3. 媒体窗口轻微浮起，使用浅色表面和柔和环境阴影；内容卡和正文不批量加阴影。
4. 圆角只保留少数语义级别，不能每个块都换一个半径。
5. 所有状态都必须可读、可聚焦、可降级；hover/focus 不能导致布局位移。

### 6.2 提议 token

以下 token 是 v0.25.9 正式视觉基线；Engineering 必须从共享 token 层替换旧暖白/棕红系统，不允许页面私有覆盖形成第二种风格。

| 角色 | 建议 token | 用途 |
| --- | --- | --- |
| 画布 | --color-canvas: #F8FAFC | 全站背景 |
| 主表面 | --color-surface: #FFFFFF | 更新卡、媒体窗口、行动区表面 |
| 轻表面 | --color-surface-subtle: #F1F5F9 | 更新卡、收束行动区、轻状态 |
| 主文字 | --color-text: #111827 | 标题与正文；不是纯黑 |
| 次文字 | --color-text-muted: #64748B | 说明、metadata、事实边界 |
| 边界 | --color-border: #E2E8F0 | 必要控件边界和可见焦点辅助 |
| 主动作 | --color-accent: #1769E0 | 主要按钮、active、主要链接 |
| 动作 hover | --color-accent-strong: #0F56C7 | hover/pressed/focus 辅助 |
| 焦点环 | --focus-ring: #2563EB | focus-visible |
| 媒体阴影 | --shadow-media: 0 18px 48px rgba(15,23,42,.10) | 仅媒体窗口及必要行动区 |
| 控件阴影 | --shadow-control: 0 4px 16px rgba(15,23,42,.08) | 仅 hover/pressed 的轻量状态 |

禁止：

- 纯黑按钮；
- 以装饰线、分割线、发光渐变和玻璃拟态表达层次；
- 使用不同色系让每个模块成为独立品牌卡；
- 让阴影、圆角或动画替代真实内容层级。

### 6.3 字体与文字角色

建议从编辑式 serif-led 视觉切换到界面优先的 sans-led 视觉，同时保留现有字体 fallback 的可用性：

~~~text
Display / Heading / Body / Meta：
Noto Sans SC → PingFang SC → Microsoft YaHei → sans-serif

Wordmark：
Inter → -apple-system → BlinkMacSystemFont → sans-serif
~~~

- 全站桌面和手机使用同一角色，不因断点换另一套字体；
- H1 先保证“Robotaxi运营平台”完整，再调整字号和宽度；
- 中文正文不强行使用 <br> 控制视觉稿行数；
- 行高、最大宽度和段间距负责多行说明的清晰归属；
- 内容 task 可以改正文，不可以在正文中加入布局控制字符或私有字号。

### 6.4 共享组件合同

| 组件 | 责任 | 允许内容 task 改什么 | 不允许改什么 |
| --- | --- | --- | --- |
| SiteHeader | 网站名、一级导航、active、移动菜单 | 无日常运营字段 | 路由、菜单层级、标签、交互状态和视觉 token |
| LatestUpdateCard | Robotaxi 真实 release 版本、更新时间和产品入口 | 无；只消费已验证 release reference | 版本号、目标、卡片存在性、页面顺序 |
| ProductHero | 一个 H1、说明、边界、动作组 | 标题、说明、边界、可编辑补充描述 | H1 数量、动作语义、外链安全策略 |
| ShowcaseModule | 一个 module 的说明和对应媒体 | label、shortDescription、loopRelation、mediaId | 组件列数、对象拆分方式、媒体安全状态 |
| MediaStage | 独立 mediaId、image/video/empty/loading/failed/revoked、比例和产品入口 | 批准 media 的引用、alt/caption/src/ratio | 自动继承其他模块媒体、伪造媒体、越权链接 |
| 页面底部行动区（ClosingAction） | 当前全部模块之后的再次入口 | title、summary、button label | 是否位于底部、目标产品类型、页面层级 |

| ResumeActions | 查看 HTML 简历、下载 PDF 简历 | 只消费已确认 ResumeArtifactRef | 猜测路径、修改上游简历、把候选当公开事实 |

| 媒体 | 使用 manifest ratio；当前批准视频保持 8:5；浅表面、柔和阴影、圆角 16px |
| module 内部 | label → shortDescription 12–16px；说明组与媒体属于同一 module |
| module 之间 | 96–120px；不能靠重复 margin 或空段落实现 |
| 页面底部行动区（ClosingAction） | 当前全部 module 后，距离最后 module 96–120px；浅色宽幅行动区 |
| footer | 页面底部行动区后自然流末端；只有一行 |

Web 首屏截图只用于验证第一屏层级、宽度和首个 module 的归属。它不要求在 1067px 内展示完整 4 个 module，也不把首屏截断当成内容缺失。

### 7.2 Mobile：390 × 844

| 项目 | 合同 |
| --- | --- |
| 视口 | 390 × 844 |
| shell | 左右 gutter 20px；窄于 360px 时可降到 16px |
| header | logo + 菜单按钮一行；菜单打开时保留现有可访问焦点管理 |
| 更新卡 | 仍在 Hero 之前，不因手机空间删除 |
| Hero | 标题、说明、边界自然多行；不人为插入换行 |
| 动作组 | 两个动作必须同一行；按钮文字不得折成两行；必要时使用紧凑内边距但不能缩小触控目标 |
| module 顺序 | 说明在上，媒体在下；不能沿用桌面“媒体在上”的顺序 |
| module 内部 | label → shortDescription 12–16px；说明整体 → 对应媒体 20–24px |
| module 之间 | 56–72px；显著大于同一 module 的 20–24px |
| 归属判断 | 先看到一组完整说明，再看到同组媒体；下一个 module 开始前保留 56–72px |
| 媒体 | 按 manifest ratio 渲染，不裁切成无法辨认的窄条；失败显示同位置 fallback |
| 页面底部行动区（ClosingAction） | 当前全部 module 后出现，不进入首屏；标题/说明/按钮可自然多行，保持同一行动区 |
| footer | 只有一行 inline 内容，不拆成两行、两列或第二组链接 |

### 7.3 额外稳健性检查

1600 × 1067 和 390 × 844 是视觉定稿视口；另外只做实现稳健性检查，不改变两套基线：

- 320px：无水平滚动、动作仍可操作；
- 375px：动作不折行、媒体不溢出；
- 768px：桌面双栏尚未成立时按紧凑单栏自然流；
- 1280px：shell 不超过最大宽度。

## 8. Robotaxi 模块流和媒体事实

### 8.1 当前初始内容

产品初始正文完全复用当前文件，不在本方案中改写文案。四个模块是四个独立媒体关系，未来分别绑定四种不同内容；当前为了完整验收视觉和能力，允许四个独立 `mediaId` 字段都引用同一个已批准视频：

| 顺序 | module id | 当前 label | 当前内容文件 | 当前媒体状态 |
| --- | --- | --- | --- | --- |
| 1 | robotaxi-operations-current-simulation | Robotaxi车队运营 | .content-workspace/content/products/robotaxi.json | mediaId=robotaxi-evidence-fleet-operations-console-v1，已批准公开 |
| 2 | robotaxi-operations-city-spatial-progress | Robotaxi经营规划与供给 | 同上 | 初始引用同一批准视频；未来独立替换 |
| 3 | robotaxi-operating-model | Robotaxi运营决策及经分 | 同上 | 初始引用同一批准视频；未来独立替换 |
| 4 | robotaxi-operating-metrics-overview | 运营自动化模拟 | 同上 | 初始引用同一批准视频；未来独立替换 |

title、intro、boundary、shortDescription、loopRelation、action.href 均使用当前文件原值。初始重复引用不复制 MP4 文件，也不把一条证据描述成四条证据；它只是四个独立模块的临时内容配置。内容 task 后续可以逐项替换，不需要修改页面 JSX 或 CSS。

### 8.2 无媒体模块的正常处理

没有 `mediaId` 是合法内容状态，不是异常。对没有批准媒体的 module：

1. 仍生成 MediaStage 位置，以便说明与媒体的结构关系稳定；
2. 使用同样的比例、圆角、间距和 loading/fallback 状态；
3. 显示克制的“演示内容准备中/暂无已发布演示”状态，不能显示假缩略图或假运行结果；
4. 不生成指向 Robotaxi 的 action，除非该 module 有合法、安全且已批准的 action；
5. 内容 task 后续补齐批准媒体后，页面不需要改结构，只更新 mediaId 和媒体 manifest。

能力验收必须分别覆盖 `ready:image`、`ready:video`、`empty`、`loading`、`failed/revoked`，所有状态保持相同槽位、比例和对象归属。

### 8.3 媒体窗口行为

- 继续使用现有批准媒体生命周期：approved + public + active + hash 可验证才可投影；
- 批准视频默认 `autoplay + muted + loop + playsinline`，不显示原生 controls；只让进入视口的媒体播放，离开视口暂停，避免四个媒体同时消耗资源；
- `prefers-reduced-motion` 下使用静态预览或暂停状态，不把自动运动作为理解内容的前提；
- 有合法 Robotaxi action 时，整个媒体窗口可作为进入入口，但可见和无障碍名称都必须是“进入 Robotaxi 运营平台”；
- 点击媒体只打开 Robotaxi 入口，不触发播放/暂停；键盘 Enter 触发同一安全跳转；
- 没有合法 action 时，媒体只读显示并保留可访问 alt/caption；
- video、image、失败和空状态都占据同一 module 的媒体槽位，不能导致下一个 module 跳到无法判断的位置。

## 9. 页面底部行动区（ClosingAction）的真实含义

这里的 ClosingAction 不是“关闭页面”的设计术语。它就是页面最下方、用户读完当前全部说明/媒体对象后的再次行动区：

~~~text
最后一个 ShowcaseModule
    ↓ 96–120px（Web）/ 56–72px（Mobile）
页面底部行动区（ClosingAction）
    ├─ 标题：初始可使用 Robotaxi运营平台
    ├─ 说明：初始可复用当前 boundary，后续由内容 task 更新
    └─ 按钮：进入 Robotaxi 运营平台
    ↓ 40–48px
单行 SiteFooter
~~~

它允许内容 task 在不改结构的情况下把标题或说明调整为“试试我的新作品”等更有行动感的表达，但必须继续说明这是 Robotaxi 运营平台，并保持既定安全目标。它不是关闭按钮，不是弹窗，不是新的产品菜单，不是主页入口，也不替代 Hero 的首屏动作。

建议的初始结构化值（仅为当前内容 fixture，不是最终文案）：

~~~json
{
  "closing": {
    "title": "Robotaxi运营平台",
    "summary": "这是 Robotaxi 运营中台的模拟作品，用于展示经营结构与产品交互；页面数据不代表真实城市运营或企业经营结果。",
    "action": {
      "label": "进入 Robotaxi 运营平台",
      "href": "https://robotaxi.xingbuild.top/"
    }
  }
}
~~~

## 11. Engineering 实现合同

### 11.1 产品结构

- 保留现有 PageDefinition、Home/Showcase/Reading/Collection 组合、RichDocument、SystemStage 和安全 action；在这些基线上扩展共享 ReleaseNotice、ProductHero、ActionGroup、ShowcaseFlow/ShowcaseModule、MediaStage、ClosingAction、ResumeActions；
- `/products` 渲染当前 Practice 的 4 个 module，不为每个 module 创建页面私有 JSX；不投影 Brief rail；
- module 内说明与媒体由同一个 ShowcaseModule 组件拥有；
- 每个 module 独立读取 `mediaId`；media 缺失时渲染正常 empty fallback，不删除对象关系、不伪造媒体；
- action 统一经过 safePracticeAction 或同等 allowlist 校验。
- 首页按“定位 → 双动作 → 最新产品完整投影 → 最新短文 → Footer”组合，不增加 About 收束；
- `/business-observations` 保持左长文/右短文且使用紧凑标题；`/observations` 和详情使用同一视觉系统；
- `/about` 使用居中 RichDocument + ResumeActions；不增加联系方式或继续阅读；提供非导航 HTML 简历投影和 PDF 下载。

### 11.2 内容能力

- 只把日常内容文案迁移到结构化 SiteContent resolver；产品身份、菜单、版本、路由、安全目标和 footer 结构保留产品 owner；
- 扩展 content/registry/content-targets.json，至少登记：
  - site.home.*
  - site.sharedCopy.*
  - products.robotaxi.heroActions.*
  - products.robotaxi.closing.*
  - products.robotaxi.module.{moduleId}.order/mediaId
  - media.robotaxi.asset.{assetId}.alt/caption
- 新增受控 `ProductReleaseReference` adapter 读取 Robotaxi 已验证 release 版本；新增 `ResumeArtifactRef` 校验 career HTML/PDF 同源身份、hash 与公开状态；
- Robotaxi manifest 不具备浏览器 CORS 时，使用 xingbuild 同源只读 adapter，只返回 `version/commit/production_url` 白名单字段并设置短缓存；上游失败时显示最后一次已验证快照和明确降级状态，不伪造最新；
- 所有数组使用稳定 id 定位；禁止按当前文案、DOM selector 或数组下标定位；
- 对每次字段变更生成 before/after hash、projectionRoutes、requires 和 ContentReleaseIntent；
- 内容包只消费已经实现的字段和媒体生命周期，不把 .content-workspace 临时文件直接当成产品事实。

### 11.3 视觉系统

- 建立唯一冷白 token 层，清理旧暖白 token 的页面私有覆盖；
- SiteHeader、SiteFooter、按钮、链接、card、媒体、阅读 shell、观察 rail 共用同一套 token；
- media stage 使用 manifest ratio 和 content-level responsive projection；
- 禁止通过页面私有 <br>、空段落、重复 margin 制造节奏；
- hover、focus、loading、error、fallback 不改变列数、标题位置、媒体比例或滚动上下文。

### 11.4 测试与证据

- schema/content checks：当前 JSON、扩展字段、4 个稳定 module、独立 mediaId、媒体批准状态和安全链接；
- route checks：/products 的 active nav 是 B端产品，页面 H1 是 Robotaxi运营平台，无主页替代；
- visual checks：1600 × 1067 和 390 × 844 截图；
- responsive checks：320、375、768、1280 的溢出和折叠；
- accessibility checks：heading 顺序、focus-visible、44px touch target、媒体 alt/fallback、reduced motion；
- media behavior checks：可视区域视频 autoplay/muted/loop/playsinline、无 controls，离屏暂停；点击/Enter 只跳转；Reduced Motion 使用静态状态；
- state checks：image/video/empty/loading/failed/revoked 不改变槽位比例与页面结构；
- reuse checks：用第二个产品 fixture 证明 ShowcaseFlow 不依赖 Robotaxi 页面私有 JSX/CSS；修改一个 module 的 mediaId 不影响其他 module；
- page checks：首页无 About 收束；经营观察保持左长文/右短文；About 居中且 HTML/PDF 目标存在、hash 匹配；
- content independence checks：更新一条登记内容字段后，无需改 JSX/CSS/route 即可形成独立 ContentReleaseIntent；
- production checks 继续遵守产品版本、内容兼容声明和 SitePublication Coordinator 合同。
