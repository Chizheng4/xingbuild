# v0.7.0 企业认知框架结构与视觉定稿

## 1. 文档状态

- 版本：v0.7.0
- 日期：2026-07-27
- 状态：结构与视觉已定稿，可直接进入 Engineering 实现
- 产品合同：`docs/design/v0.7.0 企业认知框架产品化方案.md`
- 内容事实源：`docs/upstream/企业经营体系、数字化与职业定位认知框架 v5.1.md`
- 视觉基线：`docs/design/xingbuild Visual System v1.md`

本文件只决定同一知识模型在桌面、手机和交互状态中的投影方式，不修改 career 权威定义，不增加第二份概念事实源。

## 2. 结论

v0.7.0 使用一套最小充分构图：

1. 桌面总览以“编辑型导读 + 四平面关系图 + 当前路径”建立整体；
2. 桌面稳定详情采用主图与右侧详情并列，主图保持探索上下文，详情承担阅读；
3. 手机总览将同一关系模型投影为纵向语义流，不缩小桌面关系图；
4. 手机概念详情使用独立页面，不使用底部抽屉承载完整定义；
5. 企业业务架构九个固定视角全部保留，但默认局部总览突出六个主路径视角，其余三个进入同页“完整视角”组；
6. 第一轮只完整实现并验证一条路径：

```text
企业经营体系总览
→ 数字化实现
→ 企业业务架构
→ 业务对象
→ 对象
→ Robotaxi 应用
```

根本理由：读者既需要保留“我从哪里来”的整体上下文，又需要稳定阅读定义。桌面宽度足以让两者并存；手机宽度不足，独立详情页比抽屉更适合长定义、依赖、辨析、来源和应用，同时浏览器历史天然承担返回。

## 3. 三项定稿决策

### 3.1 桌面详情：右侧稳定详情区

采用非遮挡式双区构图：

```text
┌──────────────────────────────────────────────────────────────┐
│ 返回作品  /  企业经营体系认知框架                  框架说明 │
│ 企业经营体系：从整体进入局部、概念、底层与应用              │
├───────────────────────────────────────┬──────────────────────┤
│                                       │ 认知路径              │
│ 当前总览 / 局部结构                   │ 总览 › 数字化实现     │
│                                       │ › 企业业务架构        │
│ [企业现实] [经营与架构设计]           │                      │
│        ↘        ↓                      │ 企业业务架构          │
│       [数字化实现] → [运行反馈]        │ 概念性质 · 架构       │
│                                       │ 权威定义……            │
│ 当前节点、直接上下游和关系线高亮       │                      │
│ 其他节点降低权重但不消失               │ 直接依赖 / 上层结构   │
│                                       │ 底层追溯 / 应用       │
└───────────────────────────────────────┴──────────────────────┘
```

布局合同：

- `>= 1200px`：内容版心最大 1280px；探索区约 7.5–8 列，详情区约 4–4.5 列，间隔 48–64px；
- `900–1199px`：探索区约 58–62%，详情区约 38–42%，间隔 32–40px；
- 详情区宽度目标 360–420px，顶部在框架工具区下方 sticky；
- 详情不是覆盖层，不遮挡节点，不改变主图几何位置；
- 选择概念时只更新详情内容、路径和图中状态，不让页面发生宽度或垂直跳动；
- 详情较长时页面正常滚动；详情内部不建立第二个滚动容器；
- “阅读全文”仅在内容超过稳定详情责任时进入独立概念页。

不选下方面板，因为它会把图与定义拆成上下两个阅读现场；不选节点内展开，因为会破坏关系图几何结构并造成累计布局位移。

### 3.2 手机详情：独立概念页

手机不使用底部抽屉承载完整概念详情。点击节点进入独立概念页，URL 表达当前概念，浏览器返回恢复总览中的原节点、滚动位置和展开状态。

```text
┌──────────────────────┐
│ ← 返回数字化实现     │
│                      │
│ 总览 › 数字化实现    │
│ › 企业业务架构       │
│                      │
│ 企业业务架构         │
│ 概念性质 · 架构      │
│                      │
│ 权威定义……           │
│                      │
│ 回答的问题           │
│ 直接依赖             │
│ 上层结构             │
│ 底层追溯             │
│ Robotaxi 应用        │
│ 来源与版本           │
└──────────────────────┘
```

理由：

- 详情包含定义、性质、依赖、辨析、应用和来源，不是快速确认信息；
- 320–390px 中抽屉若保留总览上下文，会让两者都不可读；
- 独立页具有稳定 URL、浏览器历史、深链接和无 JavaScript 降级能力；
- 快速预览不是手机必需状态，点击即进入稳定详情，减少一次无价值触控。

### 3.3 企业业务架构：九个视角保留，六个主路径突出

九个固定视角全部进入首版数据模型和局部结构页：

1. 业务领域；
2. 企业能力；
3. 价值流；
4. 企业职能；
5. 组织责任；
6. 业务流程；
7. 业务对象与事件；
8. 业务规则；
9. 业务指标。

默认首屏突出六个主路径视角：

- 企业能力；
- 价值流；
- 业务流程；
- 业务对象与事件；
- 业务规则；
- 业务指标。

业务领域、企业职能、组织责任保留在同页“完整视角”组，并与主路径保持可达和同等权威，但降低初始视觉权重。此分组只服务学习顺序，不改变九视角定义、关系和地位。

```text
经营目标
   ↓
企业能力 → 价值流 → 业务流程
                      ↓
              业务对象与事件
                 ↙       ↘
             业务规则   业务指标

完整视角：业务领域 / 企业职能 / 组织责任
```

首版 Robotaxi 下钻只需让“业务对象与事件”中的“业务对象”进入底层“对象”，不需要同时为九个视角建设完整应用案例。

## 4. 页面与状态

### 4.1 路由责任

工程可按现有路由方式选择具体路径命名，但必须具备以下稳定状态：

| 状态 | 必须可恢复的信息 |
| --- | --- |
| 作品入口 | 框架作品摘要和进入行动 |
| 框架总览 | 四个平面、主关系和默认阅读入口 |
| 平面聚焦 | 当前平面及其局部结构 |
| 桌面概念详情 | 当前概念、认知路径、主图聚焦状态 |
| 独立概念页 | 概念标识、来源、返回探索现场 |
| 底层追溯 | 上层概念到基础性质的明确关系 |
| Robotaxi 应用 | 概念在场景中的映射和证据边界 |

建议 URL 使用稳定标识，不使用中文标题作为唯一键。概念标题可以更新，稳定标识不能随文案变化。

### 4.2 桌面总览

阅读顺序：

1. 返回作品与内容类型；
2. 页面标题和一段范围说明；
3. “如何阅读”轻提示；
4. 四平面总览；
5. 当前推荐路径；
6. 来源与版本说明。

四平面不是四张卡片，而是同一个有向关系结构。使用空间分组、标题层级和有语义的连接线，不使用阴影、圆角卡片墙或装饰性边框。

### 4.3 桌面概念详情

右侧详情内部固定顺序：

1. 认知路径；
2. 正式名称；
3. 概念性质与所属平面；
4. 权威定义；
5. 回答的问题；
6. 直接依赖；
7. 上层结构；
8. 底层追溯；
9. 应用入口；
10. 来源与版本；
11. 需要时的“阅读全文”。

“相关概念”与“定义依赖”必须使用不同标签和位置，不能用一组外观相同的链接混合表达。

### 4.4 手机总览

手机总览使用纵向语义流：

```text
企业现实
  ↓ 设计对象
经营与架构设计
  ↓ 转化为
数字化实现
  ↓ 进入并支持
企业运作
  ↓ 产生
事实与经营结果
  ↓ 分析和决策
下一轮经营与架构设计
```

每个节点显示名称和最多一句责任说明。关系文字独占节点之间的关系行，但不使用无意义序号。点击节点进入独立详情；“数字化实现”可在当前页展开一层局部结构后再进入概念，避免手机总览一次暴露全部术语。

### 4.5 手机概念详情

- 18–22px 页面边距；
- 返回操作位于内容页头之后、路径之前，触控目标至少 44px；
- 路径允许换行，显示完整层级，不做横向滚动；
- 标题使用 `--type-page-title` 的手机范围；
- 权威定义作为第一核心内容，不先堆叠属性表；
- 属性以定义列表或语义分组呈现，不模拟桌面双列；
- 每个大组之间 48–64px，同组内容 16–28px；
- 来源和版本位于正文末尾，使用 EvidenceNote 语义。

## 5. 完整下钻路径

### 5.1 路径与每步任务

| 步骤 | 当前视图 | 用户获得的理解 | 下一行动 |
| --- | --- | --- | --- |
| 1 | 企业经营体系总览 | 四个平面及反馈关系 | 选择“数字化实现” |
| 2 | 数字化实现聚焦 | 业务设计如何进入产品、数据、技术和工程 | 选择“企业业务架构” |
| 3 | 企业业务架构详情 | 九个固定视角及其责任 | 选择“业务对象与事件”中的“业务对象” |
| 4 | 业务对象详情 | 业务对象是企业业务架构中的限定表达 | 追溯“对象” |
| 5 | 对象详情 | 对象是底层基础概念性质 | 进入 Robotaxi 应用 |
| 6 | Robotaxi 应用 | Robotaxi 作为被创建、使用、改变和追踪的业务对象 | 返回对象、业务对象或总览 |

### 5.2 路径视觉语义

- “所属结构”使用路径导航；
- “定义依赖”使用向上追溯行动；
- “应用”使用场景入口；
- “相关概念”只作为旁路，不加入主路径；
- 当前步骤用文字状态和 `aria-current` 表达，不能只靠赭色；
- 路径中的数字仅在说明“步骤顺序”时出现，不在页面标题或概念节点旁作装饰编号。

### 5.3 Robotaxi 应用边界

应用页只陈述上游快照已经固定的映射：

> 单台 Robotaxi 是企业用于提供出行服务的实体资源和业务对象；车队履约能力由车辆、技术、人员、规则、流程、设施、伙伴和数字化系统共同形成，不能把单台车辆本身定义为企业能力。

页面必须同时显示证据边界：这是认知框架在 Robotaxi 场景中的分析应用，不代表真实城市 Robotaxi 经营结果已经被验证。

## 6. 视觉系统增量合同

### 6.1 视觉角色

- 页面标题与概念名称：编辑型衬线；
- 路径、关系、性质、来源与操作：无衬线；
- 权威定义：编辑型衬线正文，字号高于普通说明一级；
- 架构节点：名称使用衬线或中等字重无衬线，关系标签使用无衬线；
- 强调色只表达当前、链接和可交互状态，不给整个节点填充强调色。

### 6.2 空间责任

```text
FrameworkPage
└─ FrameworkSectionFlow      负责页面大区之间 72–112px
   ├─ FrameworkHeader        负责标题内部关系
   ├─ FrameworkExplorer      负责主图与详情之间 32–64px
   │  ├─ StructureView       只负责节点和关系内部构成
   │  └─ ConceptDetail       只负责详情内部构成
   └─ EvidenceNote           只负责来源说明内部构成
```

父级 flow 负责同级对象间距；节点、详情字段和来源说明不能各自添加外部上下 margin。桌面与手机只缩放距离，不改变“对象内部紧、对象之间疏”的关系。

### 6.3 线条与边界

- 线条只表达“驱动、形成、进入、产生、反馈、定义依赖”等真实关系；
- 每条跨节点连接必须有可读文字或可被辅助技术读取的等价说明；
- 详情区与主图以空白和列关系分隔，不增加装饰竖线；
- 当前路径可加强线宽或不透明度，非当前关系降低权重但保持可辨；
- 不使用手绘、渐变、3D、阴影和装饰箭头。

## 7. 响应式投影

| 视口 | 总览 | 详情 | 导航 |
| --- | --- | --- | --- |
| 1200px 以上 | 四平面关系图，主图与详情并列 | 右侧 sticky 稳定详情 | 现有桌面页头 |
| 900–1199px | 压缩空白、保留双区 | 右侧稳定详情 | 现有紧凑页头 |
| 640–899px | 关系图转为分组纵向结构 | 独立概念页 | 现有紧凑页头 |
| 520–639px | 单列纵向语义流 | 独立概念页 | 557px 附近继续现有紧凑内联页头 |
| 520px 以下 | 单列纵向语义流 | 独立概念页 | 现有全屏手机菜单 |

结构切换点以内容可读性为准，约在 900px 由双区进入单列；520px 只负责全站导航切换，不能被框架页面重新定义。

## 8. 交互与可访问性

- 桌面 hover 预览只显示名称、一句话定义、性质和“查看详情”；
- focus 与 hover 获得同等信息；
- click 进入稳定详情，URL 更新且浏览器前进/后退可恢复；
- Escape 只关闭临时预览或清除桌面选中态，不使用户离开独立详情页；
- 选择新概念后，屏幕阅读器获得简短状态通知；
- 主图按合理 DOM 阅读顺序排列，不能依赖绝对定位顺序表达语义；
- 连接关系必须有文本等价物；
- 当前节点同时使用文字、形态或线宽，不只使用颜色；
- 动画只用于 120–220ms 状态过渡，`prefers-reduced-motion` 时取消；
- 无 JavaScript 时，概念列表、定义和主路径仍按文档顺序可阅读。

## 9. 工程对象边界

建议对象责任：

| 对象 | 责任 |
| --- | --- |
| `concept` | 单一概念定义、性质、平面、来源和版本 |
| `relation` | 起点、终点、关系类型、关系标签和方向 |
| `view` | 从同一模型选择节点、关系和布局语义 |
| `application` | 概念到场景的映射与证据边界 |
| `pathState` | 当前概念、祖先路径、来源视图和返回位置 |

视图组件不得复制概念定义。桌面图、手机纵向流、详情页和应用页只能消费同一对象模型。

## 10. 实现与验收范围

### 10.1 必须实现

- 作品入口摘要；
- 框架总览默认状态；
- 数字化实现聚焦状态；
- 企业业务架构局部视图；
- 企业业务架构、业务对象、对象三个概念详情；
- Robotaxi 应用；
- 桌面预览和右侧详情；
- 手机纵向总览和独立详情；
- URL、返回、焦点与状态恢复；
- 来源和证据边界；
- 无 JavaScript 可读降级。

### 10.2 自动测试

- 概念标识唯一，定义非空，来源版本存在；
- 关系起终点均存在，关系类型在允许集合内；
- 九个企业业务架构视角完整且名称与上游一致；
- 主路径六步可从模型中连续解析；
- 桌面选中态与 URL 同步；
- 手机详情返回恢复来源视图、滚动位置和展开状态；
- hover 信息可由 focus 和 click 获得；
- 320px 不产生整页横向滚动；
- 非语义序号未被自动生成；
- `npm run release:check` 通过。

### 10.3 真实浏览器验证

在 1440、1024、768、557、520、390、320px 验证：

- 页面标题和中文词组不发生破坏语义的拆分；
- 四平面主关系和关系标签可读；
- 双区切换为单列时没有内容丢失或顺序改变；
- 详情字段层级、段落上下关系和大组间距一致；
- 520px 上下的全站导航遵守 v0.6.2 合同；
- 完整下钻、返回和 Robotaxi 应用路径可完成；
- 键盘焦点、Escape、浏览器前进后退和恢复行为可预测；
- 浅色品牌不随系统或 Codex 深色模式改变。

## 11. 明确不做

- 不修改 career 权威概念、定义、性质或九视角；
- 不把约 30 个概念全部建设成完整应用案例；
- 不新增一级导航；
- 不做自由画布、缩放平移、自动图布局编辑器；
- 不做多层 tooltip、概念比较多窗口、收藏或学习进度；
- 不做 AI 问答、后台管理或自动同步发布；
- 不把桌面图等比缩小到手机；
- 不为视觉完整而补造没有上游来源的关系；
- 不发布、不推送、不修改域名。

## 12. 完成判断

本结构与视觉阶段已经完成：三项待定均已决策，桌面、手机和完整下钻路径形成单一工程合同，未发现需要改变权威概念、五种视图、首版根本范围或核心路径的冲突。

当前尚未完成的是 Engineering 实现、真实页面验证、本地提交与版本标签。它们必须由 Engineering 按项目发布规则分别报告，不能由本设计文档提前宣称。
