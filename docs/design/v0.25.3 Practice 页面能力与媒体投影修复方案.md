# v0.25.3 Practice 页面能力与媒体投影修复方案

## 目标

修复 `/products` Practice 页面在独立内容发布后的视频运行时投影，并补齐 Hero 的稳定展示合同。产品版本只建设能力，不重写内容事实、不替代独立内容发布。

```mermaid
flowchart LR
  A[登记媒体目标] --> B[content manifest]
  B --> C[practice reader]
  C --> D[Practice module]
  D --> E[/products DOM video]
  C --> F[projection test]
```

## 根因与边界

- 根因是 manifest 身份字段与 runtime reader 的索引依据不一致：校验接受的 manifest 没有 `practiceId`，reader 却依赖 `manifest.practiceId`。
- Engineering 负责统一既有登记关系、reader、构建与测试；内容 task 不修改 `src/`、schema、CSS 或伪造 manifest 字段。
- 内容仍使用独立 `ContentReleaseIntent`；产品 build 不读取独立内容根，启用内容时由正式协调器组装。

## 实现范围

1. Hero 标题与说明居中，说明支持受控语义换行，不允许 HTML 注入。
2. CTA 只有在字段注册、链接安全和键盘可达合同同时存在时才实现；未登记则不渲染。
3. 媒体 reader 使用现有 target/practice 登记关系完成映射，不新增第二套身份字段。
4. 统一覆盖 content check、reader projection、构建产物和真实 `/products` DOM 的验收。

## 验收

- 桌面与移动端 Hero 居中、换行稳定、无溢出。
- `findPractice("robotaxi")` 的绑定模块具有已审核视频 `media.src`。
- `/products` DOM 存在视频元素，媒体 URL、hash、目标与 package 证据一致。
- 其余三个模块 media 为空，不生成占位媒体。
- 内容关闭构建不包含独立内容正文/媒体。
- 既有四个模块、完整菜单、路由和上游事实不变。
- `npm run check`、`release:prepare`、专项测试、closeout、preflight、真实页面验收通过。

## 非目标

- 不重发已发布内容包，不修改内容正文、审核、来源或媒体事实。
- 不纳入内容发布状态机、内容隔离、架构视图等其他候选。
