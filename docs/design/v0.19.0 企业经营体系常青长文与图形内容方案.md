# v0.19.0 企业经营体系常青长文与图形内容方案

## 1. 单一结论

企业经营体系不是需要持续开发的交互式架构应用，而是一篇长期维护、可以不断
增加章节与图形的常青长文。

本版本停止扩展 `ArchitectureExplorer`。公开页面复用现有文章阅读系统：

```text
EvergreenArticlePublication
→ 自动目录
→ RichDocument
→ figure（响应式SVG）
→ 内容审核与独立发布
```

Mermaid、LikeC4 只作为内容生产阶段的开源CLI和可编辑图形源，不作为公开
网站运行时。网站不保存手工节点坐标、关系控制点或逐图组件代码。

## 2. 目标与成本边界

目标：

1. 今天完成一个最小、稳定、可发布的文章阅读能力；
2. 后续增加十张图、章节或更深内容时只做内容工作；
3. 保留 career 上游事实边界和现有网站视觉语言；
4. 不再为单张图重复产品、视觉和Engineering迭代。

明确不做：

- 不建设多视图架构应用、节点浏览器、画布、缩放、平移或节点详情弹层；
- 不引入新的前端图形运行时；
- 不逐条手写SVG、节点位置或关系路径；
- 不重写企业经营事实、定义和关系；
- 不修改Header、Footer、一级导航、Robotaxi或Observation Brief；
- 不追求当前 v0.18.0 效果图的像素复刻。

## 3. 页面责任

`/business-observations` 保持经营观察来源页，并继续保留最新观察rail。

桌面完整布局：

```text
主内容区 952px
├── sticky目录约160px
├── 24px关系间距
└── 文章正文约768px

主内容区 → 24px → 最新观察rail 304px
```

- 页面标题、摘要和文章属于同一个企业经营体系对象；
- 目录在文章标题和摘要之后开始sticky，不进入全局Header；
- 正文自然滚动，不建立内部滚动容器；
- 无有效Brief时仍按既有规则取消空rail。

紧凑与手机：

- 主内容区转为单列；
- 目录改为正文前的原生可展开目录；
- 图形宽度不超过正文；
- 同一图由构建从同一图源自动生成手机产物；若390px不可读，内容工作拆分图或调整源的语义结构/layoutPreset，不用页面特例或手工坐标解决；
- 不通过横向滚动或缩小桌面图解决手机可读性。

## 4. 内容对象

新增 `EvergreenArticlePublication`：

```text
id
slug
title
summary
status
updatedAt
blocks[]
sources[]
```

首个且当前唯一对象：

```text
content/articles/enterprise-operating-system.json
```

`blocks` 只使用 RichDocument 已有受控语法，并对 figure 增加受控字段：

```text
type: figure
sourcePath
renderer
layoutPreset?
alt
caption
```

其中：

- `sourcePath` 是内容作者唯一声明的可编辑 `.mmd/.c4` 路径，不投影给读者；
- `renderer` 选择构建期 Mermaid 或 LikeC4 CLI；`layoutPreset` 只表达图的语义布局选择；D2保留为未来可选adapter，未锁定前不属于当前内容合同；
- desktop/mobile SVG路径由构建从同一source自动生成、校验和投影，不是内容作者手写字段；
- alt说明图回答的问题，不复制caption；
- caption说明图的范围和阅读方式，不展示治理标签。

## 5. 自动目录

目录只从文章中 `level=2/3` 且具有稳定 `id` 的 heading block生成。

桌面：

- sticky位置必须避开全局sticky Header；
- H2为主目录，H3为从属目录；
- 点击使用真实锚点URL；
- 当前章节可以通过滚动观察进行克制高亮；
- 键盘、刷新和直接访问 `#anchor` 均成立。

手机：

- 使用原生 `details/summary`；
- 选择目录项后关闭目录并到达目标；
- 每个目标具有正确 `scroll-margin-top`；
- 不使用覆盖页面的第二套导航。

## 6. 图形生产与网站边界

图形源由 `$system-visual-modeling` 或内容责任task根据问题选择：

- Mermaid：流程、状态、生命周期、时序；
- D2：未来可选 adapter；未锁定 CLI 与专项验收前，不属于当前内容合同；
- LikeC4：多视角系统结构的可编辑源。

统一流水线：

```text
批准事实
→ 可编辑图形源
→ 锁定版本CLI渲染
→ 自动生成desktop/mobile SVG
→ figure block
→ 内容检查
→ 人工阅读验收
→ 内容发布
```

构建或检查必须验证：

- 源文件存在且可重新生成；
- SVG不是失败后的旧产物；
- 文件无脚本、外链执行或不受控嵌入；
- 两档生成产物存在、与同一source hash一致；
- alt、caption和必要来源完整；
- 390px无横向溢出，文字仍可阅读。

公开页面只展示生成后的静态SVG。读者点击图时最多打开同源完整SVG，不新增
modal、画布运行时或图形工具栏。

## 7. 首次迁移

首版只迁移现有批准事实，不新增观点：

1. 企业经营体系总览；
2. 系统边界与企业现实；
3. 经营与架构设计；
4. 数字化实现；
5. 企业运作、事实与经营结果；
6. 经营分析与反馈；
7. 来源与事实边界。

现有 `frameworkModel`、LikeC4模型和已批准说明是迁移输入。迁移完成并逐项校验
后，公开页面删除对 `FrameworkGraphRuntime`、`ArchitectureExplorer` 和手工
Projection的读取；历史文件可保留追溯，但不得继续参与生产构建。

旧链接：

```text
/business-observations?view=digital-implementation
```

必须以 replace语义兼容为：

```text
/business-observations#digital-implementation
```

## 8. 内容发布

本版本一次性建立常青文章的独立发布门槛。能力完成后，文章更新：

- 只允许一个目标 `content/articles/<slug>.json`；
- 可附带该文章引用的图形源与生成SVG；
- 不修改 `package.json`、`VERSION.md`、产品tag、页面组件或发布规则；
- 执行schema、锚点唯一性、图形源/产物、build、Sites和目标URL验证；
- 形成独立内容提交并保持既有产品版本。

具体命令可以复用现有内容发布共享能力，但必须显式接收文章slug，不得让
Observation专用字段污染 EvergreenArticlePublication。

9. 不修改其他页面、内容对象或视觉系统。

## 10. 验收

- 1440px：目录、正文和最新观察rail关系清楚，目录sticky不遮挡内容；
- 768px：文章单列或紧凑目录成立，无不可读缩略图；
- 390px：可展开目录、锚点、纵向图形和自然滚动成立；
- 所有H2/H3锚点唯一，直接URL和刷新定位正确；
- 每张图具有可编辑源、可重建SVG、alt和caption；
- 页面无图形运行时、手工坐标、节点交互或内部滚动；
- 不改写任何上游事实；
- 新增一张测试图只改图源与内容对象、再增加一个H2后，不修改React/CSS即可生成两档SVG、构建并显示；
- 删除测试内容后，正式对象通过完整release check；
- 产品实现、提交/tag、push、部署与公网验收分别回传。
