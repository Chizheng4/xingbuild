# v0.6.2 序号语义与手机导航简化方案

## 1. 结论

xingbuild 当前把序号同时用于栏目、作品、能力、主题说明和架构节点，但这些数字承担的含义不同。结果不是更结构化，而是让读者无法判断数字表示顺序、分类、重要性还是装饰。

本轮原则：

> 结构由对象、标题、对齐和空间表达；数字只表达数字本身具有的信息。

`v0.6.2` 删除无语义序号，保留时间、流程顺序、架构位置、版本和错误标识，并固定手机展开导航的最小视觉合同。

## 3. Maggie 的序号机制

Maggie 没有给每篇 Note 编号。顶部的 `79` 只出现一次，表示当前集合数量，与 “Back to Garden” 同行；它不是第 79 篇，也不是每项的序号。

每篇内容使用：

```text
小型内容类型图标
→ 标题
→ 一句说明
→ Note + 相对时间
```

列表依靠重复骨架、左侧对齐和稳定内部节奏形成秩序，不依靠 `01 / 02 / 03`。

可借鉴：

- 集合数量只在帮助理解规模时出现一次；
- 时间比序号更适合持续发布内容；
- 同类对象通过稳定结构而不是编号建立可扫描性。

不复制植物图标、Garden 隐喻、相对时间文案和 `79` 的位置。xingbuild 当前内容数量很少，显示数量没有决策价值。

## 4. xingbuild 当前问题

手机首页同时出现：

- 最新观察 `01`
- 核心作品 `02`
- 第一项作品 `01`
- 第二项作品 `02`

栏目编号和作品编号外观相似，却分别表示页面顺序和集合位置。两者都不是业务顺序、排名或稳定索引。

序号在手机上独占一行，导致栏目和对象边界被重复表达，形成“01 → 02 → 01 → 02”的认知跳转，并增加没有价值的维护责任。

其他无语义序号：

- 核心能力 `01–04`；
- “能够解决的问题”的有序列表；
- 作品详情主题说明 `01–03`；
- 作品列表 `01 / 02`。

保留：

- 观察年份 `2026`；
- 发布和更新时间；
- Robotaxi 流程 `01–05`；
- 四个平面 `01–04`；
- 版本号和 `404`。

## 5. 数字使用决策

```text
顺序是否影响含义？
├─ 是 → 使用序号
└─ 否
   是否存在明确排名或稳定引用？
   ├─ 是 → 使用索引
   └─ 否
      是否是时间、数量、版本或标识？
      ├─ 是 → 使用对应语义格式
      └─ 否 → 不显示数字
```

数字字段不应为了表现方便进入内容模型。删除 `work.index`，SectionIntro 不再接受纯装饰编号。

## 6. 手机展开导航

### 6.1 Maggie 实测

- 第一项顶部约 101px；
- 字体约 25.3px，衬线，字重 400；
- 行高约 37.9px；
- 相邻项起点相差约 53px，即约 15px视觉间隔；
- 10 个一级栏目，无说明、编号和日期；
- 展开后锁定背景滚动。

### 6.2 xingbuild 实测

- 第一项顶部约 100px；
- 字体约 23px，衬线，字重 500；
- 行高约 33.4px；
- 触控高度 56px；
- 相邻项起点相差约 68px，即 12px项间距；
- 3 个一级栏目；
- 展开后锁定背景滚动。

### 6.3 决策

xingbuild 当前手机菜单结构正确，不需要模仿 Maggie 压缩：

- 只保留 `观察 / 作品 / 关于我`；
- 不增加说明、英文、序号、数量或日期；
- 保持 23–25px 编辑型衬线；
- 保持 52–56px 触控高度；
- 项间距 8–12px；
- 第一项位于页头下方 24–32px；
- 当前项使用强调色，不增加前缀或图标；
- 保持滚动锁定、关闭按钮、Escape 和焦点恢复。

字重从 500 调整为 400 只有在真实 Noto Serif SC 截图证明更清楚时才执行；本轮默认不改。
