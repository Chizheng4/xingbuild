# v0.4.0 视觉系统工程化升级方案

## 1. 迭代定位

`v0.4.0` 不重新设计 xingbuild 的信息架构，也不重新编写内容。它把 `v0.3.1` 已经成立的阅读路径升级为稳定的 Visual System v1。

本轮因果链：

```text
当前视觉方向成立
    ↓
但数值和组件责任仍散落
    ↓
跨页面、跨断点容易出现字体和空间漂移
    ↓
建立语义 token、稳定字体角色和组件边界
    ↓
以后可以低成本迭代且保持同一品牌
```

## 2. 当前事实与差异

### 2.1 已经成立

- 暖白、墨色、赭色方向稳定；
- `观察 / 作品 / 关于我` 结构稳定；
- 首页阅读顺序、重点观察和紧凑归档已经形成；
- 长文具备桌面目录和手机折叠目录；
- 装饰性横线、边框和重复身份信息已在 `v0.3.1` 精简；
- 手机菜单已经具备独立状态和可访问交互。

### 2.2 需要升级

1. 颜色只有基础变量，没有完整语义状态和 surface 对比合同。
2. 字号仍以组件数值定义，缺少 display、page-title、reading、meta 等语义 token。
3. 空间存在大量 18、26、38、52、66 等离散数值，难以形成稳定节奏。
4. 手机端将主要衬线角色整体换成无衬线，品牌连续性不足。
5. `9px / 10px` 仍用于部分架构和必要元数据，阅读和可访问性风险偏高。
6. 单个 `styles.css` 和 `App.jsx` 同时承担过多责任，继续迭代容易产生局部覆盖。
7. 当前 Google Fonts `@import` 的加载和跨地区稳定性尚未形成合同。
8. 仅有 900px 和 520px 两层断点，部分平板和窄桌面主要依靠自然挤压。

## 3. 设计目标

### 3.1 用户结果

- 读者无需适应页面，就能识别标题、摘要、元数据、正文、证据和操作；
- 中文长文在桌面和手机都保持轻松、稳定的连续阅读；
- 作品和观察属于同一网站，但能通过密度和组件表达各自对象差异；
- 页面缩放时不发生品牌和字体角色突变。

### 3.2 工程结果

- 颜色、字体、字号、行高、空间、版心和断点由语义 token 控制；
- 稳定组件从 `App.jsx` 分离，但不引入过度抽象；
- CSS 按 token、基础、布局、组件和页面责任组织；
- 视觉规则有自动检查和真实浏览器验收；
- 后续局部调整不需要扫描整个项目寻找同义硬编码。

## 4. 本轮页面设计

### 4.1 首页

- 核心陈述桌面提升到 `display` 层级，形成更明确的作者主题；
- 标题最大宽度收紧，避免字面铺满页面；
- 手机继续使用衬线 display，但控制在 36–40px；
- Hero 与“最新观察”的距离由流体空间控制；
- 最新观察、作品、关于我不改变内容顺序；
- 不恢复状态卡、所在地和重复作者说明。

### 4.2 观察列表

- 年份、元数据、标题、摘要使用稳定 token；
- 元数据不得小于 12px；
- 普通归档通过密度而非降低到不可读字号实现紧凑；
- 手机继续两层结构，不模拟桌面对齐。

### 4.3 正文

- 桌面正文目标宽度调整为 680–720px；
- 正文字号提升到约 18px，手机约 17px；
- 正文继续使用 Noto Serif SC；
- 目录、元数据、来源和边界使用无衬线；
- H2、段落、列表、引用、代码、图注建立独立规则；
- 保留现有“本文讨论的问题”，但修正 surface 内文字对比度。

### 4.4 作品

- 保持问题优先的内容顺序；
- 作品标题和问题陈述使用衬线；
- 状态、更新时间和证据边界使用无衬线；
- 架构图小字提升，手机节点保持可读；
- 首页仍不展示完整架构图。

### 4.5 关于我

- 保持当前证据导向顺序；
- 定位、关键问题和代表项目建立统一排版角色；
- 桌面页内目录和手机单列目录使用同一目录组件语义；
- 不新增履历事实，不改写上游来源。

## 5. 组件与文件落点

建议 Engineering task 在分析现有依赖后采用以下最小拆分：

```text
src/
├─ App.jsx
├─ pages/
│  ├─ HomePage.jsx
│  ├─ ObservationsPage.jsx
│  ├─ ObservationPage.jsx
│  ├─ WorksPage.jsx
│  ├─ WorkPage.jsx
│  └─ AboutPage.jsx
├─ components/
│  ├─ site/
│  ├─ content/
│  ├─ reading/
│  └─ works/
├─ content/siteContent.js
├─ styles.css
└─ styles/
   ├─ tokens.css
   ├─ foundations.css
   ├─ layout.css
   ├─ components.css
   └─ pages.css
```

拆分原则：

- 只拆稳定、重复和独立验证的责任；
- 不引入状态管理框架；
- 不改变轻量路由机制，除非现有实现阻碍拆分；
- 不为视觉系统引入 UI 组件库；
- 不改变 Sites 构建和发布合同。

## 6. 实施阶段

### 阶段 A：视觉 token

- 建立颜色、字体、字号、行高、空间、版心和断点 token；
- 移除组件里的同义硬编码；
- 固定浅色模式，不添加自动深色覆盖；
- 验证对比度和字体回退。

### 阶段 B：基础与布局

- 建立页面容器、阅读宽度、stack、cluster 和 grid 的最小布局规则；
- 把页面间重复的版心、区块和标题关系收敛；
- 加入 1200 / 900 / 640 内容断点或等价的内容驱动规则。

### 阶段 C：组件

- 分离 SiteHeader、HeroStatement、SectionIntro；
- 分离 ObservationFeature、ObservationRow、ArticleHeader、ArticleToc；
- 分离 WorkSummary、ArchitectureDiagram、EvidenceNote；
- 页面只负责编排和数据传入。

### 阶段 D：页面适配

- 首页；
- 观察列表；
- 短观察；
- 分析长文；
- 作品列表和详情；
- 关于我；
- 手机菜单和目录状态。

### 阶段 E：验证与收口

- 自动检查；
- 真实字体加载检查；
- 五个视口的页面验证；
- 修正视觉漂移和溢出；
- `npm run release:check`；
- 设计 QA；
- 本地提交和 `v0.4.0` 标签。

## 7. 明确不做

- 不改网站名称和作者名称；
- 不改一级导航；
- 不新增或改写职业、作品和 Robotaxi 事实；
- 不增加深色主题；
- 不复制 Canela 或 Maggie 的视觉资产；
- 不增加花园、生长阶段、插画或新内容类型；
- 不增加 CMS、搜索、筛选、Build Log 和自动分发；
- 不推送 GitHub、不发布 EdgeOne、不修改域名；
- 不以重构名义更换 React、Vite 或 Sites 架构。

## 8. 验收标准

### 8.1 视觉

- 首页核心陈述具有明确 display 层级，但中文换行自然；
- 桌面与手机保留同一衬线标题和阅读正文角色；
- 元数据和必要说明不小于 12px，图注不小于 11px；
- 正文宽度、字号和行高符合 Visual System v1；
- 颜色对比满足文档合同；
- 没有装饰性边框、卡片和阴影回潮；
- 没有自动暗色切换。

### 8.2 响应式

- 1440、1024、768、390、320 五个视口无整页横向溢出；
- 手机菜单与目录保持独立可访问状态；
- 架构图在手机重新排列且文字可读；
- 页面缩放过程中无字体角色或背景颜色突变。

### 8.3 工程

- token、基础、布局、组件和页面责任可以从文件结构识别；
- 页面不复制内容事实；
- 组件不复制作品状态判断；
- 没有无依据的新依赖；
- 当前内容与 Sites 测试继续通过；
- 新增视觉系统合同测试；
- `npm run release:check` 通过。

### 8.4 状态

完成时必须分别报告：

- 实现完成；
- 自动检查完成；
- 真实浏览器验证完成；
- 设计 QA 完成；
- 本地提交和标签完成；
- GitHub 推送状态；
- EdgeOne 发布状态。

## 9. 升级后的长期收益

`v0.4.0` 的价值不只是“更像参考网站”，而是建立一套可以持续复用的视觉对象和工程责任：

```text
新增观察
  → 使用既有内容对象与阅读组件

新增作品
  → 使用既有作品、证据和架构组件

调整视觉
  → 修改语义 token 或明确组件

适配新尺寸
  → 调整布局合同，不改内容事实
```

这使网站后续可以高频迭代，同时降低页面之间产生视觉分叉的风险。
