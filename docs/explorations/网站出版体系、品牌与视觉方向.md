## 2. 网站的本质

xingbuild 不只是展示已经完成的作品，而是连接三个连续活动：

```text
持续观察与判断
        ↓
形成方法、系统和作品
        ↓
用经历、结果和证据说明作者能够提供的价值
```

对应的顶层栏目是：

```text
观察              作品                关于我
正在思考什么      已经构建什么        谁在构建、凭什么可信
```

网站、微信公众号和 X 是不同发布渠道，不是三份相互独立的内容源。网站保存可长期引用的权威版本，其他渠道保存适合各自媒介的表达投影。

## 3. 品牌结构

### 3.1 名称层级

推荐采用双层身份：

```text
xingbuild
金星 · Xingjin
```

- `xingbuild`：网站名称、作品体系和长期发布载体。
- `金星 · Xingjin`：作者身份和职业信用来源。
- `Jin Xing`：姓名拼音顺序，只在确有英文姓名规范需要时使用。

### 3.2 公开表达边界

以下内容是设计背景，不直接转写成网站文案：

- “让我自己的优势增长”；
- “持续积累并产生社会价值”；
- “个人长期记录”；
- 名称中每个字母的解释。

网站应通过持续内容、作品质量、事实证据和更新历史让访问者得出这些判断，而不是由作者直接宣称。

### 3.3 页头建议

桌面：

```text
xingbuild
金星 · Xingjin                         观察   作品   关于我
```

手机：

```text
xingbuild                    菜单
```

作者身份可在菜单或首页定位区出现，避免手机页头过度拥挤。

## 4. 内容对象

### 4.1 观察 Observation

定义：由作者主动发布的 Robotaxi、企业经营、数字化以及相关领域的短文、分析和阶段性判断。

最小字段：

```text
id
slug
title
summary
body
format
topics
status
publishedAt
updatedAt
canonicalUrl
distribution
```

`format` 可逐步使用：

- `brief`：一个事实变化和一个核心判断；
- `analysis`：较完整的因果链和结论；
- `update`：研究或作品的阶段性进展；
- `essay`：形成稳定结构的长文。

第一阶段不在导航中暴露这些类型，只在列表和文章元数据中辅助识别。

### 4.2 作品 Work

定义：已经形成相对稳定结构、可以说明问题、边界、方法、实现状态和证据的系统或认知成果。

首批作品：

- Robotaxi 经营闭环模拟平台；
- 企业经营体系与数字化认知框架。

作品不是文章集合。相关文章可以关联作品，但不能替代作品本身的目标、架构、状态和证据。

### 4.3 关于我 Profile

`关于我` 组织：

```text
当前定位
能够解决的问题
工作经历
代表项目成果
能力与责任演进
简历
当前方向
联系方式
```

工作经历和项目成果继续遵守：

```text
问题 → 责任 → 判断与行动 → 结果 → 证据 → 能力沉淀
```

### 4.4 动态 Build Log

定义：由代码提交、版本发布、作品状态等可验证事实自动形成的建设记录。

它不同于“观察”：

- 观察是作者观点；
- 动态是系统事实。

当前阶段只保留对象和服务边界，不加入顶层导航，也不在第一轮实施。

## 6. 页面布局方向

### 6.1 首页桌面

使用编辑型十二列网格，不把三个栏目做成三个等宽卡片。

```text
页头：品牌 / 作者 / 导航

定位区：
左 7—8 列：一句核心判断与研究范围
右 4—5 列：当前关注、最新更新、作品状态

最新观察：
日期 / 主题 / 标题 / 摘要

置顶作品：
作品名称 / 解决的问题 / 当前状态 / 证据边界

关于我入口：
简短定位 / 经历 / 简历 / 联系
```

现有巨大口号应降低高度，让高频回访者更快看到最新内容。

### 6.2 观察列表

借鉴 `lixiaolai.com/articles` 的高密度归档逻辑：

- 按年份组织；
- 日期、主题、标题形成稳定列；
- 不为每篇文章使用大卡片；
- 摘要只在最新或重点内容出现；
- 初期不增加复杂搜索和筛选。

### 6.3 作品

作品列表保持 xingbuild 已有的架构表达优势，但从首页摘要升级为独立详情：

- 问题与目标；
- 系统边界；
- 业务架构；
- 产品、数据与工程实现；
- 当前状态；
- 证据与局限；
- 相关观察。

### 6.4 关于我

借鉴 `lixiaolai.com/about` 的“页内目录 + 长页面分区”骨架，但不照搬成果清单和中英文重复。

桌面采用左侧页内目录、右侧主体；手机改为单列目录和内容。优先保证浏览路径，不追求一次展示所有材料。

## 7. 视觉方向

### 保留

- 桌面暖白底、编辑型衬线标题、克制赭色强调；
- 手机白底、无衬线层级、蓝色强调；
- 精确线条、编号、日期和版本信息；
- 直接的业务架构图；
- 内容、组件和视觉令牌分离。

### 调整

- 降低首页口号对首屏的占用；
- 建立文章列表所需的紧凑文字层级；
- 页头同时容纳品牌、作者和三个栏目；
- 给长内容增加正文宽度、页内目录和阅读节奏；
- 让作品图和文章图承担不同视觉职责。

### 不采用

- 图形 Logo；
- 手绘、水彩、植物、风景或装饰性隐喻；
- 为模仿参考网站而增加登录、地图、跑马灯或 GitHub 热力图；
- 大量中英文重复；
- 把所有内容包装成卡片；
- 用“News”混合作者观点和工程活动。

## 9. 工程演进原则

第一阶段采用最小充分架构：

```text
结构化内容文件
    ↓
字段与关联校验
    ↓
页面投影、主题索引和年份归档
    ↓
网站权威版本
    ↓
微信公众号与 X 的渠道适配
```

暂不引入：

- 数据库；
- 后台 CMS；
- 用户账号；
- 评论系统；
- 独立微服务；
- 全自动外部发布。

当文章数量、发布频率或跨渠道协作成本达到明确阈值后，再把内容写入、排期和分发升级为独立服务。
